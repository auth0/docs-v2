An agent-linked client can be the client of a standard login flow — authorization code, implicit, CIBA, device, MFA, password, passkey, or refresh token grant — rather than performing a token exchange. In this case, the subject remains the user. The agent identity does not appear in the top-level `sub` claim. Instead, a single-level `act` claim is added so the agent is identifiable in the token.

## Issued token

```json
{
  "iss": "https://YOUR_AUTH0_DOMAIN/",
  "sub": "auth0|user123",
  "sub_profile": "user",
  "client_id": "agent-linked-client-id",
  "client_profile": "ai_agent",
  "aud": "https://resource-api.example.com",
  "scope": "read:data",
  "exp": 1711820400,
  "iat": 1711816800,
  "act": {
    "sub": "agt_1a2b3c",
    "sub_profile": "ai_agent",
    "client_id": "agent-linked-client-id"
  }
}
```

The `sub_profile` and `client_profile` claims are only present when [enabled on the resource server](/docs/ai-agents-mcp/agents-as-principal/agent-token-flows#configure-resource-server-to-receive-agent-entity-profile-claims).
