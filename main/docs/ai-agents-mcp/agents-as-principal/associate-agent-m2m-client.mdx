Once [registered as a first-class identity in Auth0](/docs/ai-agents-mcp/agents-as-principal/register-an-agent), you can associate an agent with machine-to-machine (M2M) clients. An agent can be associated with multiple M2M clients. This is useful when you want one logical agent identity with a single `agent_id` visible in tokens and logs across multiple clients, such as separate clients per environment or region.
The `agent_id` is stored on the client object, and associations are managed dynamically.

Once you associate an agent with a M2M client, tokens issued by that client will have the agent's identity as the subject (`sub`) for client credentials grants or as the actor (`act`) for token exchange and standard login flows.

## Associate a client at creation

Set the `agent_id` when creating a client via `POST /api/v2/clients`:

```json
{
  "name": "My AI Client",
  "agent_id": "agt_abc123XYZ"
}
```

## Retrieve the association

Once an `agent_id` association has been made, `GET /api/v2/clients/{id}` returns it in the response body:

```json
{
  "name": "My AI Client",
  "agent_id": "agt_abc123XYZ"
}
```

## Associate an existing client

You can associate an existing client with the Auth0 Dashboard or Management API.

<Tabs><Tab title="Auth0 Dashboard">

1. Navigate to the **Dashboard > Agents**, select the agent, and then the **Applications** tab. 
2. Select **Add Application** and the applicable applications in the modal.
3. Select **Add Applications**.

Once successfully added, the application should show up under the **Applications** tab.

</Tab><Tab title="Management API">

Associate existing clients with an agent via `PATCH /api/v2/clients/{id}`:

```json
{
  "agent_id": "agt_abc123XYZ"
}
```

</Tab></Tabs>

## Remove the association

Set `agent_id` to `null` to dissociate a client from its agent:

```json
{
  "agent_id": null
}
```

After dissociation, new tokens issued by the client no longer carry agent identity. Existing tokens remain valid until expiry.
