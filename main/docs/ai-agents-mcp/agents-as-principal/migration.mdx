## Existing M2M clients

Existing M2M clients are unaffected unless you explicitly associate them with an agent. Association is opt-in and reversible.

To migrate an existing M2M client to agent-backed identity:

1. Create an agent: `POST /api/v2/agents`
2. Associate the client: `PATCH /api/v2/clients/{id}`
3. Existing tokens issued by the client remain valid until expiry.
4. New tokens issued after association include `agent_id` in logs and carry `sub_profile`/`client_profile` claims if enabled on the resource server.

## Resource servers

To receive `sub_profile` and `client_profile` claims, set `agent_subject_claims: 'auth0-v1'` on the target resource server configuration. This is opt-in per resource server.

**Example:**

```http
PATCH /api/v2/resource-servers/{id}
Content-Type: application/json

{
  "agent_subject_claims": "auth0-v1"
}
```

<Callout type="warning">
Review `sub` parsing in downstream services before enabling. Services that validate or parse the `sub` claim format may need updates to handle `ai_agent` as a valid entity type.
</Callout>
