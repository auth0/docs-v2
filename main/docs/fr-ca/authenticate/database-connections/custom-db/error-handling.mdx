Vous pouvez recevoir des erreurs provenant de bases de données personnalisées. Vous pouvez également renvoyer des erreurs à partir de scripts d’action de base de données à des fins de dépannage.

<div id="custom-database-error-types">
  ## Types d’erreurs de base de données personnalisée
</div>

Les connexions de base de données peuvent renvoyer les erreurs suivantes :

| Erreur                                                                              | Script d’action        | Se produit lorsque...                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------------------------------------------------- | ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `new WrongUsernameOrPasswordError(`<br />`  <email or user_id>, <message>`<br />`)` | Login                  | Les identifiants de l’utilisateur sont invalides. Les [codes de type d’événement consignés](/docs/fr-ca/deploy-monitor/logs/log-event-type-codes) sont les suivants : <ul><li>`fu` (nom d’utilisateur ou adresse courriel invalide) avec une chaîne vide pour `user_id` si aucun argument ou un premier argument évalué à faux est transmis.</li> <li>`fp` (l’utilisateur existe, mais le mot de passe est invalide) avec une valeur `user_id` de `auth0\|<first_argument>` si un premier argument évalué à vrai est transmis.</li> </ul> |
| `new ValidationError(`<br />`  <user_exists>, <message>`<br />`)`                   | Create                 | L’utilisateur existe déjà dans votre base de données.                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `callback(<null>,<false>)`                                                          | Change Password        | Le mot de passe de l’utilisateur n’a pas été mis à jour.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `callback(<null>)`                                                                  | Get User               | L’utilisateur est introuvable.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `new UnauthorizedError(<message>)`                                                  | Tous les scripts Login | Un problème est survenu lors de la tentative d’accès à la base de données. Il s’agit de la méthode privilégiée pour communiquer les erreurs des bases de données personnalisées à l’interface utilisateur.                                                                                                                                                                                                                                                                                                                          |
| `new Error(<message>)`                                                              | Tous les scripts Login | Un problème est survenu lors de la tentative d’accès à la base de données.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `error code: auth0_idp_error;` `user already exists`                                | Create                 | La migration automatique vers Auth0 est désactivée et vous tentez de créer un utilisateur qui existe déjà dans votre magasin d’utilisateurs externe ou dans Auth0.                                                                                                                                                                                                                                                                                                                                                                  |
| `error code: auth0_idp_error;` `user already exists`                                | Delete                 | La migration automatique vers Auth0 est désactivée et vous tentez de supprimer un utilisateur à l’aide de scripts de base de données personnalisée.<br /><br />L’erreur peut également s’afficher sous la forme « Erreur ! Un problème est survenu lors de la suppression de `user@example.com` » ou « Erreur de sandbox : veuillez implémenter le script Delete pour cette connexion de base de données ».                                                                                                                         |

<div id="return-errors">
  ## Renvoyer des erreurs
</div>

Vous pouvez renvoyer des erreurs depuis des scripts d’action de base de données à l’aide de [la fonction `callback`](/docs/fr-ca/authenticate/database-connections/custom-db/custom-database-connections-scripts#callback). Par exemple :

```js wrap lines
callback(new ValidationError('email-too-long', 'Email is too long.'));
```

Si vous utilisez Lock, vous pouvez [personnaliser les messages d’erreur](/docs/fr-ca/customize/login-pages/classic-login/customize-lock-error-messages) en les ajoutant au dictionnaire.

<div id="troubleshoot-errors">
  ## Résoudre les erreurs
</div>

Testez le script à l’aide du bouton **Try**.

Si vous n’obtenez pas le résultat attendu ou si vous recevez une erreur, utilisez les [Journaux en temps réel d’Actions](/docs/fr-ca/customize/actions/actions-real-time-logs), ajoutez des instructions `console.log()` à votre script, puis réessayez la connexion. La sortie de `console.log()` s’affiche dans la fenêtre des Journaux en temps réel d’Actions.

Vous pourriez rencontrer des erreurs lorsque vous utilisez des scripts d’action pour importer, créer ou supprimer des utilisateurs. Utilisez `console.logs` pour vérifier que l’erreur est bien causée par l’utilisation de scripts d’action.
