Le script Get User implémente la fonction exécutée pour déterminer si un utilisateur existe ou non. Nous recommandons de nommer cette fonction `getUser`.

Ce script est requis pour la [migration automatique vers Auth0](/docs/fr-ca/manage-users/user-migration/configure-automatic-migration-from-your-database) et, lorsque la migration n’est pas activée, il peut être requis selon les opérations configurées pour la connexion. Auth0 recommande fortement que le `user_id` retourné dans le profil utilisateur soit permanent et cohérent : pour un utilisateur donné, le script Get User doit retourner le même `user_id` à chaque exécution. Consultez [Retourner un user&#95;id cohérent](#return-a-consistent-user-id) pour en savoir plus.

Lorsque **Import Users to Auth0** est activé, le script Get User s’exécute lorsqu’un utilisateur tente de s’inscrire afin de vérifier s’il existe déjà dans le magasin d’utilisateurs externe.

Le script Get User s’exécute également lorsqu’un utilisateur tente de :

* Modifier son adresse courriel (script [Change Email](/docs/fr-ca/authenticate/database-connections/custom-db/templates/change-email))
* Se connecter (script [Login](/docs/fr-ca/authenticate/database-connections/custom-db/templates/login))
* Modifier son mot de passe (script [Change Password](/docs/fr-ca/authenticate/database-connections/custom-db/templates/change-password))

Lorsque **Import Users to Auth0** est désactivé, le script Get User s’exécute lorsqu’un utilisateur tente de s’inscrire afin de vérifier s’il existe déjà dans le magasin d’utilisateurs externe. Si l’utilisateur existe déjà dans le magasin d’utilisateurs externe, le script Create ne s’exécute pas.

Le script Get User s’exécute également lorsqu’un utilisateur tente de :

* S’inscrire (script [Create](/docs/fr-ca/authenticate/database-connections/custom-db/templates/create))
* Modifier son adresse courriel (script [Change Email](/docs/fr-ca/authenticate/database-connections/custom-db/templates/change-email))
* Modifier ou réinitialiser son mot de passe (script [Change Password](/docs/fr-ca/authenticate/database-connections/custom-db/templates/change-password))

<div id="get-user-function">
  ## Fonction Get User
</div>

La fonction `getUser` doit :

* Envoyer l’identifiant de l’utilisateur à l’API de la base de données externe.
* Retourner les données du profil de l’utilisateur si celui-ci a été trouvé.
* Retourner une erreur s’il est impossible de déterminer si l’utilisateur existe ou non.

<div id="definition">
  ### Définition
</div>

La fonction `getUser` accepte deux paramètres et renvoie une fonction `callback` :

```js lines
getUser(email, callback): function
```

| Paramètre  | Type     | Description                                                                   |
| ---------- | -------- | ----------------------------------------------------------------------------- |
| `email`    | String   | L&#39;adresse courriel de l&#39;utilisateur.                                  |
| `callback` | Fonction | Utilisé pour transmettre une erreur ou des données de profil dans le pipeline |

Voici un pseudo-exemple en Javascript montrant comment vous pourriez implémenter la fonction `getUser` :

```javascript lines expandable
function getUser(email, callback) {
  // Envoyer l'identifiant utilisateur à l'API de base de données externe
  let options = {
    url: "https://example.com/api/search-users",
    body: {
      email: email
    }
  };

  send(options, (err, profileData) => {
    // Retourner une erreur dans le callback s'il y a eu un problème lors de la recherche de l'utilisateur
    if (err) {
      return callback(new Error("Could not determine if user exists or not."));
    } else {
      // Retourner null dans le callback si l'utilisateur n'a pas été trouvé, retourner les données de profil dans le callback si l'utilisateur a été trouvé
      if (!profileData) {
        return callback(null);
      } else {
        let profile = {
          email: profileData.email,
          user_id: profileData.userId
        };

        return callback(null, profile);
      }
    }
  });
}
```

<div id="callback-function">
  ## Fonction `callback`
</div>

La fonction `callback` sert à transmettre les données du profil utilisateur ou les données d’erreur dans le pipeline.

<div id="definition-2">
  ### Définition
</div>

La fonction `callback` accepte jusqu’à deux paramètres et renvoie une fonction :

```js lines
callback(error[,profile]): function
```

| Paramètre | Type  | Obligatoire | Description                                      |
| --------- | ----- | ----------- | ------------------------------------------------ |
| `error`   | Objet | Obligatoire | Contient les données d’erreur.                   |
| `profile` | Objet | Facultatif  | Contient les données de profil de l’utilisateur. |

<div id="return-the-user-profile-user-found">
  ### Retourner le profil de l’utilisateur (utilisateur trouvé)
</div>

<Warning>
  Les données de profil renvoyées par le script Get User pour un utilisateur doivent être cohérentes avec celles renvoyées par le script Login.
</Warning>

Si l’utilisateur est trouvé, transmettez la valeur `null` au paramètre `error` et les données du profil de l’utilisateur au paramètre `profile`, sous [forme normalisée](/docs/fr-ca/manage-users/user-accounts/user-profiles/normalized-user-profile-schema) :

```js lines
return callback(null, {
    username: "username",
    user_id: "my-custom-db|username@domain.com",
    email: "username@domain.com",
    email_verified: false,
    user_metadata: {
        language: "en"
    },
    app_metadata: {
        plan: "full"
    },
    mfa_factors: [
      {
        phone: {
          value: "+15551234567"
        }
      },
    ]
});
```

En plus des champs standard, vous pouvez inclure les champs `user_metadata`, `app_metadata` et `mfa_factors`.

<div id="return-a-consistent-user_id">
  ### Retourner un user_id cohérent
</div>

Auth0 utilise le `user_id` retourné par le script Get User pour identifier l’utilisateur dans votre tenant. Pour un utilisateur donné, cette valeur doit être **cohérente** : le script Get User doit retourner le même `user_id` chaque fois qu’il s’exécute pour cet utilisateur. Générez le `user_id` à partir d’une propriété stable et permanente de l’enregistrement source (comme la clé primaire de la base de données), et non d’une valeur qui change d’une exécution à l’autre.

<Callout icon="file-lines" color="#0EA5E9" iconType="regular">
  Retourner un `user_id` non cohérent peut créer des utilisateurs en double ou orphelins et interrompre les flows qui dépendent de la stabilité de l’identifiant.
</Callout>

Générez le `user_id` à partir d’une propriété stable de l’enregistrement source afin que le même utilisateur soit toujours mappé à la même valeur.

```js lines
return callback(null, {
    // `user.id` est la clé primaire immuable de votre base de données
    user_id: "my-custom-db|" + user.id,
    email: user.email,
    email_verified: user.email_verified
});
```

Ne générez pas de `user_id` nouveau ou aléatoire à chaque requête. Par exemple, ne retournez pas un UUID nouvellement généré. Cela produit un identifiant différent chaque fois que le script s’exécute pour un même utilisateur.

```js lines
const { v4: uuidv4 } = require("uuid");

return callback(null, {
    // Anti-modèle : une nouvelle valeur est générée à chaque exécution, et Auth0 la traite chaque fois comme un nouvel utilisateur
    user_id: uuidv4(),
    email: user.email,
    email_verified: user.email_verified
});
```

<div id="return-no-user-profile-user-not-found">
  ### Ne retourner aucun profil utilisateur (utilisateur introuvable)
</div>

Si l&#39;utilisateur est introuvable, transmettez une valeur `null` au paramètre `error` et omettez le paramètre `profile` :

```js lines
return callback(null);
```

<div id="return-an-error">
  ### Retourner une erreur
</div>

Si une erreur se produit, transmettez les données d’erreur au paramètre `error` avec les renseignements pertinents sur la cause du problème :

```js lines
return callback(new Error("My custom error message."));
```

Pour en savoir plus, consultez [Résoudre les problèmes liés aux bases de données personnalisées](/docs/fr-ca/authenticate/database-connections/custom-db/error-handling).

  async function getUserAsync(email, callback) {
    //à mettre à jour à mesure que de nouvelles versions d’axios deviennent disponibles (https://auth0-extensions.github.io/canirequire/#axios)
    const axios = require("axios@0.22.0");

    let response;

    try {
      response = await axios.post(
        //stockez l’URL de l’API dans les paramètres de la connexion afin de mieux prendre en charge les environnements SDLC
        configuration.baseAPIUrl + "/getUser",
        //identifiants de l’utilisateur transmis dans le corps de la requête
        {
          email: email,
        },
        {
          timeout: 10000, //mettez fin à l’appel de façon appropriée si la requête expire afin que le script puisse exécuter la fonction de rappel nécessaire
          headers: {
            //sécurise l’appel d’API avec la clé apiKey stockée dans les paramètres de la connexion.
            //approche simple et rapide, mais l’utilisation de jetons M2M est plus sécuritaire, car
            // un secret ne doit pas être partagé entre le client et l’API.
            "x-api-key": configuration.apiKey,
          },
        }
      );
    } catch (e) {
      if (e.response.status === 404) {
        //en supposant que l’API renvoie 404 lorsqu’aucun utilisateur correspondant à l’adresse courriel ou au nom d’utilisateur indiqué n’est trouvé
        return callback(null, null);
      }
      //fonction de rappel pour tout autre type d’erreur
      return callback(new Error(e.message));
    }

    try {
      let user = response.data;

      //si vous utilisez plusieurs connexions de base de données personnalisées dans votre tenant, préfixez le
      //user_id avec une clé propre à la connexion, p. ex. : "connName|" + user.user_id
      //cela garantit des ID utilisateur uniques dans l’ensemble des connexions de base de données
      return callback(null, {
        user_id: user.user_id,
        email: user.email,
      });
    } catch (e) {
      return callback(new Error(e.message));
    }
  }
