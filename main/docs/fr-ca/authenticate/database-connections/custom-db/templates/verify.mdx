Le script Verify implémente la fonction exécutée pour marquer l’état de vérification de l’adresse courriel d’un utilisateur dans une base de données externe. Nous recommandons de nommer cette fonction `verify`.

Ce script est utilisé uniquement dans les scénarios d’authentification héritée et est requis pour assurer le soutien de la vérification de l’adresse courriel de l’utilisateur. Une adresse courriel vérifiée est essentielle à un certain nombre de scénarios de flux de travail dans Auth0, et l’implémentation de ce script offrira ce soutien d’emblée.

S’il est activé, ce script est exécuté lorsqu’un utilisateur clique sur le lien contenu dans le courriel de vérification envoyé par Auth0.

<div id="verify-function">
  ## Fonction Verify
</div>

La fonction `verify` doit :

* Mettre à jour l’attribut `email_verified` (ou l’attribut équivalent) dans le profil de l’utilisateur stocké dans la base de données externe.
* Retourner `true` si l’action de mise à jour a réussi.
* Retourner une erreur si l’action de mise à jour a échoué.

<div id="definition">
  ### Définition
</div>

La fonction `verify` accepte deux paramètres et renvoie une fonction `callback` :

```js
verify(email, callback): function
```

| Paramètre  | Type     | Description                                                                      |
| ---------- | -------- | -------------------------------------------------------------------------------- |
| `email`    | String   | Adresse courriel de l&#39;utilisateur.                                           |
| `callback` | Function | Utilisé pour transmettre l&#39;erreur ou les données de profil dans le pipeline. |

Voici un exemple en pseudo-JavaScript montrant comment vous pourriez implémenter la fonction `login` :

```javascript lines
function verify(email, callback) {
  // Envoyer un courriel à l'API de base de données externe
  let options = {
    url: "https://example.com/api/verify",
    body: {
      email: email
    }
  };

  send(options, (err) => {
    // Retourner une erreur dans le callback si la mise à jour a échoué
    if (err) {
      return callback(new Error(email, "My custom error message."));
    } else {
      // Retourner true dans le callback si la mise à jour a réussi
      return callback(null, true);
    }
  });
}
```

<div id="callback-function">
  ## Fonction de rappel
</div>

La fonction `callback` sert à transmettre les données du profil utilisateur ou les données d’erreur au sein du pipeline.

<div id="definition-2">
  ### Définition
</div>

La fonction `callback` accepte jusqu’à deux paramètres et retourne une fonction :

```js
callback(error, [verified]): function
```

| Paramètre  | Type    | Obligatoire | Description                                                                                                                                                               |
| ---------- | ------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `error`    | objet   | Obligatoire | Contient les données d’erreur.                                                                                                                                            |
| `verified` | Boolean | Facultatif  | Contient une valeur indiquant l’état de vérification de l’utilisateur dans la base de données externe (`true` ou `false`). Obligatoire seulement si la valeur est `true`. |

<div id="return-a-success">
  ### Renvoyer un succès
</div>

Si l’état de vérification de l&#39;utilisateur a été mis à jour avec succès dans la base de données externe, passez la valeur `null` pour le paramètre `error` et la valeur `true` pour le paramètre `verified` :

```js
callback(null, true);
```

<Callout icon="file-lines" color="#0EA5E9" iconType="regular">
  Le script Verify ne modifie pas la valeur de l&#39;attribut `email_verified` dans le profil Auth0 de l&#39;utilisateur, quelle que soit la valeur renvoyée dans la fonction `callback`.

  Pour mettre à jour l&#39;attribut `email_verified` dans le profil Auth0 de l&#39;utilisateur, vous devez inclure l&#39;attribut `email_verified` et sa valeur dans l&#39;objet de profil de l&#39;utilisateur renvoyé par les scripts [Login](/docs/fr-ca/authenticate/database-connections/custom-db/templates/login) et [Get User](/docs/fr-ca/authenticate/database-connections/custom-db/templates/get-user).
</Callout>

<div id="return-an-error">
  ### Retourner une erreur
</div>

Si une erreur se produit, le paramètre `error` doit contenir des renseignements pertinents sur la nature du problème :

```js
return callback(new Error("My custom error message."));
```

  function verify(email, callback) {
    // Ce script doit marquer l'adresse courriel de l'utilisateur actuel comme
    // vérifiée dans votre base de données.
    // Il est exécuté chaque fois qu'un utilisateur clique sur le lien de vérification envoyé par courriel.
    // Ces courriels peuvent être personnalisés à l'adresse https://manage.auth0.com/#/emails.
    // Vous pouvez présumer sans risque que l'adresse courriel de l'utilisateur existe déjà dans votre base de données,
    // car les courriels de vérification, s'ils sont activés, sont envoyés immédiatement après une
    // inscription réussie.
    //
    // Ce script peut se terminer de deux façons :
    // 1. L'adresse courriel de l'utilisateur a été vérifiée avec succès
    //     callback(null, true);
    // 2. Un problème est survenu lors de la tentative d'accès à votre base de données :
    //     callback(new Error("my error message"));
    //
    // Si une erreur est retournée, elle sera transmise à la chaîne de requête de la page
    // vers laquelle l'utilisateur est redirigé après avoir cliqué sur le lien de vérification.
    // Par exemple, retourner `callback(new Error("error"))` et rediriger vers
    // https://example.com redirigerait vers l'URL suivante :
    //     https://example.com?email=alice%40example.com&message=error&success=false
    const msg = 'Veuillez implémenter le script Verify pour cette connexion de base de données ' +
      'à l\'adresse https://manage.auth0.com/#/connections/database';
    return callback(new Error(msg));
  }

          return callback(err);
        }
        callback(null, rowCount > 0);
      });
      updateMembershipQuery.addParameter('Email', TYPES.VarChar, email);
      connection.execSql(updateMembershipQuery);
    }

    function findUserId(email, callback) {
      const findUserIdFromEmail =
        'SELECT UserProfile.UserId FROM ' +
        'UserProfile INNER JOIN webpages_Membership ' +
        'ON UserProfile.UserId = webpages_Membership.UserId ' +
        'WHERE UserName = @Username';
      const findUserIdFromEmailQuery = new Request(findUserIdFromEmail, function (err, rowCount, rows) {
        if (err || rowCount < 1) return callback(err);
        const userId = rows[0][0].value;
        callback(null, userId);
      });
      findUserIdFromEmailQuery.addParameter('Username', TYPES.VarChar, email);
      connection.execSql(findUserIdFromEmailQuery);
    }
    function verifyMembershipUser(email, callback) {
      findUserId(email, function (err, userId) {
        if (err || !userId) return callback(err);
        // le champ isConfirmed est l'indicateur de vérification de courriel
        const updateMembership =
          'UPDATE webpages_Membership SET isConfirmed = \'true\' ' +
          'WHERE isConfirmed = \'false\' AND UserId = @UserId';
        const updateMembershipQuery = new Request(updateMembership, function (err, rowCount) {
          return callback(err, rowCount > 0);
        });
        updateMembershipQuery.addParameter('UserId', TYPES.VarChar, userId);
        connection.execSql(updateMembershipQuery);
      });
    }
  }
