Lorsqu&#39;une requête implique un client lié à un agent, l&#39;environnement d&#39;exécution des Actions expose un objet `event.agent`. Cet objet est absent lorsqu&#39;aucun agent n&#39;est impliqué; le code Actions existant n&#39;est donc pas affecté.

<div id="triggers">
  ## Déclencheurs
</div>

`event.agent` est présent dans les déclencheurs suivants :

| Déclencheur            | Lorsque `event.agent` est présent                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------- |
| `credentials-exchange` | Octroi de type Client Credentials lorsque `agent_id` est défini pour le client.                         |
| `post-login`           | Code d’autorisation, échange de jetons ou flux d’appareil lorsque `agent_id` est défini pour le client. |

<div id="eventagent-object">
  ## Objet `event.agent`
</div>

L’objet `event.agent` a le schéma suivant :

```json
{
  "agent_id": "agt_72jbvv7LfRKYp59gtRLtkn",
  "agent_metadata": {
    "env": "prod"
  }
}
```

`event.client` reste inchangé ; il continue de refléter le client OAuth lié qui a authentifié la requête.

<div id="example-custom-claims-on-agent-tokens">
  ## Exemple : revendications personnalisées dans les jetons d’agent
</div>

Utilisez `event.agent` dans une action `credentials-exchange` pour ajouter le contexte de l’agent aux jetons d’accès :

```javascript
exports.onExecuteCredentialsExchange = async (event, api) => {
  if (event.agent) {
    api.accessToken.setCustomClaim('agent_env', event.agent.agent_metadata?.env);
    api.accessToken.setCustomClaim('agent_id', event.agent.agent_id);
  }
};
```

Pour en savoir plus sur la création d’Actions, consultez [Write Your First Action](/docs/fr-ca/customize/actions/write-your-first-action).
