<ReleaseStageNotice feature="Agent as Principal" stage="ea" contact="Auth0 Support" terms="true" />

Une fois l’agent [enregistré comme identité de premier ordre dans Auth0](/docs/fr-ca/ai-agents-mcp/agent-as-principal/register-an-agent), vous pouvez l’associer à n’importe quel client OAuth. Un agent peut être associé à plusieurs clients. C’est utile lorsque vous souhaitez une seule identité logique d’agent, avec un `agent_id` unique visible dans les jetons et les journaux de plusieurs clients, par exemple des clients distincts par environnement ou par région.

L’`agent_id` est stocké dans l’objet client, et les associations sont gérées de façon dynamique.

Dès que vous associez un agent à un client, les jetons émis à ce client portent l’identité de l’agent comme sujet (`sub`) dans le cas des octrois par information d’identification client, ou comme acteur (`act`) dans le cas de l’échange de jetons et des flux de connexion standards. Pour en savoir plus, consultez [Identité de l’agent dans les jetons](/docs/fr-ca/ai-agents-mcp/agent-as-principal/agent-identity-in-tokens).

<Callout icon="file-lines" color="#0EA5E9" iconType="regular">
  L’`agent_id` interne demeure l’identifiant utilisé pour gérer l’agent au moyen de la Management API, que vous ayez défini un `external_agent_id` ou non.
</Callout>

## Associer un client à la création {#associate-a-client-at-creation}

Définissez le paramètre `agent_id` au moment de créer un client avec `POST /api/v2/clients` :

<Tabs>
  <Tab title="Auth0 CLI">
    <Callout icon="file-lines" color="#0EA5E9" iconType="regular">Vous utilisez l&#39;interface de ligne de commande Auth0? Si ce n&#39;est pas déjà fait, [configurez et authentifiez votre session CLI](/docs/fr-ca/deploy-monitor/auth0-cli) avant d&#39;exécuter cette commande.</Callout>

    ```bash
    auth0 api post "clients" \
      --data '{
        "name": "My AI Client",
        "agent_id": "YOUR_AGENT_ID"
      }'
    ```
  </Tab>

  <Tab title="cURL">
    ```bash
    curl --request POST \
      --url 'https://YOUR_AUTH0_DOMAIN/api/v2/clients' \
      --header 'Content-Type: application/json' \
      --header 'Authorization: Bearer YOUR_MGMT_API_TOKEN' \
      --data '{
        "name": "My AI Client",
        "agent_id": "YOUR_AGENT_ID"
      }'
    ```
  </Tab>
</Tabs>

Si l&#39;opération réussit, Auth0 retourne l&#39;objet client avec l&#39;`agent_id` que vous avez défini.

## Récupérer le client associé à l&#39;agent {#retrieve-the-agent-associated-client}

Une fois que vous avez associé un `agent_id` à un client, envoyez une requête `GET` à `/api/v2/clients/{id}` pour obtenir l&#39;objet client :

<Tabs>
  <Tab title="Auth0 CLI">
    ```bash
    auth0 api get "clients/YOUR_CLIENT_ID"
    ```
  </Tab>

  <Tab title="cURL">
    ```bash
    curl --request GET \
      --url 'https://YOUR_AUTH0_DOMAIN/api/v2/clients/YOUR_CLIENT_ID' \
      --header 'Authorization: Bearer YOUR_MGMT_API_TOKEN'
    ```
  </Tab>
</Tabs>

Si la requête réussit, Auth0 renvoie l&#39;objet client avec l&#39;`agent_id` que vous avez défini.

## Associer un client existant {#associate-an-existing-client}

Vous pouvez associer un client existant à l&#39;aide du Auth0 Dashboard ou de la Management API.

<Tabs>
  <Tab title="Auth0 Dashboard">
    1. Accédez à **Dashboard &gt; Agents**, sélectionnez l&#39;agent, puis ouvrez son onglet **Applications**.
    2. Sélectionnez **Add Application**, puis choisissez les applications à associer à l&#39;agent dans la fenêtre modale. Vous pouvez en sélectionner plusieurs.
    3. Sélectionnez **Add Applications**.

    Une fois l&#39;ajout réussi, les applications s&#39;affichent sous l&#39;onglet **Applications** de l&#39;agent.
  </Tab>

  <Tab title="Management API">
    Associez un client existant à un agent au moyen de `PATCH /api/v2/clients/{id}` :

    <Tabs>
      <Tab title="Auth0 CLI">
        ```bash
        auth0 api patch "clients/YOUR_CLIENT_ID" \
          --data '{
            "agent_id": "YOUR_AGENT_ID"
          }'
        ```
      </Tab>

      <Tab title="cURL">
        ```bash
        curl --request PATCH \
          --url 'https://YOUR_AUTH0_DOMAIN/api/v2/clients/YOUR_CLIENT_ID' \
          --header 'Content-Type: application/json' \
          --header 'Authorization: Bearer YOUR_MGMT_API_TOKEN' \
          --data '{
            "agent_id": "YOUR_AGENT_ID"
          }'
        ```
      </Tab>
    </Tabs>

    En cas de succès, Auth0 renvoie l&#39;objet client mis à jour avec l&#39;`agent_id` que vous avez défini.
  </Tab>
</Tabs>

## Supprimer l&#39;association à l&#39;agent {#remove-the-agent-association}

Pour dissocier un client de son agent, définissez `agent_id` à `null` au moyen de `PATCH /api/v2/clients/{id}` :

<Tabs>
  <Tab title="Auth0 CLI">
    ```bash
    auth0 api patch "clients/YOUR_CLIENT_ID" \
      --data '{
        "agent_id": null
      }'
    ```
  </Tab>

  <Tab title="cURL">
    ```bash
    curl --request PATCH \
      --url 'https://YOUR_AUTH0_DOMAIN/api/v2/clients/YOUR_CLIENT_ID' \
      --header 'Content-Type: application/json' \
      --header 'Authorization: Bearer YOUR_MGMT_API_TOKEN' \
      --data '{
        "agent_id": null
      }'
    ```
  </Tab>
</Tabs>

Après la dissociation, les nouveaux jetons émis au client ne portent plus l&#39;identité de l&#39;agent. Les jetons existants demeurent valides jusqu&#39;à leur expiration.
