Lorsqu&#39;une requête met en jeu un client lié à un agent, le moteur d&#39;exécution des Actions expose un objet `event.agent`. Cet objet est absent lorsqu&#39;aucun agent n&#39;intervient, ce qui n&#39;a donc aucune incidence sur le code des Actions existant.

## Triggers {#triggers}

`event.agent` est présent dans les triggers suivants :

| Trigger                | Cas où `event.agent` est présent                                                                    |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| `credentials-exchange` | Octroi par informations d’identification client lorsque le client a un `agent_id` défini.           |
| `post-login`           | Code d’autorisation, échange de jetons ou flux d’appareil lorsque le client a un `agent_id` défini. |

## Objet `event.agent` {#eventagent-object}

L&#39;objet `event.agent` possède le schéma suivant :

```json
{
  "agent_id": "agt_72jbvv7LfRKYp59gtRLtkn",
  "agent_metadata": {
    "env": "prod"
  }
}
```

`event.client` demeure inchangé : il continue de représenter le client OAuth lié qui a authentifié la requête.

## Exemple : demandes personnalisées dans les jetons d&#39;agent {#example-custom-claims-on-agent-tokens}

Utilisez `event.agent` dans une Action `credentials-exchange` pour ajouter le contexte de l&#39;agent aux jetons d&#39;accès :

```javascript
exports.onExecuteCredentialsExchange = async (event, api) => {
  if (event.agent) {
    api.accessToken.setCustomClaim('agent_env', event.agent.agent_metadata?.env);
    api.accessToken.setCustomClaim('agent_id', event.agent.agent_id);
  }
};
```

Pour en savoir plus sur l&#39;écriture d&#39;Actions, consultez [Écrire votre première Action](/docs/fr-ca/customize/actions/write-your-first-action).
