En configurant votre tenant Auth0 comme Authorization Server de la Resource App, votre application SaaS peut accepter les requêtes [ID-JAG](https://datatracker.ietf.org/doc/draft-ietf-oauth-identity-assertion-authz-grant/) entrantes sans aucune modification de code. Vous pouvez ainsi émettre des access tokens en réponse à ces requêtes, ce qui permet aux AI agents et à d’autres applications de consommer en toute transparence votre API MCP ou SaaS au nom d’un utilisateur.

<Frame>![](/docs/images/xaa/xaa-env-setup.png)</Frame>

<div id="get-started">
  ## Démarrage
</div>

Pour configurer votre tenant Auth0 en tant que Resource App :

1. Effectuez la [configuration de l’environnement](/docs/fr-ca/ai-agents-mcp/cross-app-access/set-up-xaa-test-environment) afin de configurer votre API et d’enregistrer une Requesting App de test dans votre tenant Auth0.
2. Configurez l’enterprise IdP en suivant le guide approprié de la section Intégration d’IdP — [Okta comme IdP OIDC](/docs/fr-ca/ai-agents-mcp/cross-app-access/idp/okta-as-oidc-idp) ou [Okta comme SAML IdP](/docs/fr-ca/ai-agents-mcp/cross-app-access/idp/okta-as-saml-idp) — selon l’IdP et le protocole que vous utilisez pour vous fédérer avec celui-ci.
3. Une fois les deux parties configurées, consultez [Tests de bout en bout](/docs/fr-ca/ai-agents-mcp/cross-app-access/end-to-end-testing) pour valider le XAA flow au complet.
