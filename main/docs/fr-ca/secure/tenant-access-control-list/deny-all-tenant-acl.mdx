Dans les situations qui exigent un rejet strict du trafic, vous pouvez mettre en place une règle Deny All. Cette configuration Deny All agit comme un refus générique : tout le trafic entrant est redirigé vers votre locataire, peu importe l&#39;identifiant utilisé.

<div id="configuration-details">
  ## Détails de configuration
</div>

L&#39;élément clé de l&#39;implémentation Deny All est l&#39;attribut `match_all`. Lorsqu&#39;il est réglé à `true`, cet attribut fait en sorte que la règle contourne la correspondance de signaux précis (comme l&#39;IP ou la géolocalisation) et applique plutôt l&#39;action à toutes les requêtes visant la permission spécifiée.

<div id="example-configuration">
  ## Exemple de configuration
</div>

La configuration suivante illustre l&#39;attribut `match_all` :

```json
{
 "active": true,
 "description": "Block all traffic",
 "priority": 99,
 "rule": {
  "action": {
    "block": "true"
  },
  "scope": "tenant",
  "match_all": true
 }
}
```

| **Paramètre** | **Description**                                                                                                                                                                                                                               |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `match_all`   | Obligatoire. Doit être défini à `true`. La valeur `false` n&#39;est pas prise en charge pour les règles Deny All.                                                                                                                             |
| `priority`    | Attribuez un numéro de priorité élevé (par exemple, `99`) pour que la règle Deny All constitue la dernière étape d&#39;évaluation, ce qui permet d&#39;évaluer d&#39;abord les règles plus précises dont le numéro de priorité est inférieur. |
| `scope`       | Appliquez la permission `tenant` pour assurer une protection complète de tout le trafic entrant.                                                                                                                                              |

<div id="tenant-acl-logs">
  ## Journaux de l&#39;ACL du locataire
</div>

La journalisation standard s&#39;applique à cette règle comme à toute autre règle d&#39;ACL du locataire. Pour en savoir plus sur la journalisation des événements, consultez la [référence des événements de journal du locataire](/docs/fr-ca/secure/tenant-access-control-list/tenant-log-event-reference).
