Vous pouvez créer des [rôles](/docs/fr-ca/manage-users/access-control/rbac) à l’aide du Dashboard d’Auth0 ou de la <Tooltip tip="Management API : un produit qui permet aux clients d’effectuer des tâches administratives." cta="Voir le glossaire" href="/docs/fr-ca/glossary?term=Management+API">Management API</Tooltip>. Les rôles fonctionnent avec l’ensemble de fonctionnalités Authorization Core pour les API.

Vous pouvez créer deux types de rôles dans Auth0 :

* Rôles de tenant : s’appliquent à l’ensemble de votre tenant et peuvent être attribués à n’importe quel utilisateur.
* Rôles d’organisation : limités à une organisation précise. Les utilisateurs peuvent avoir des rôles d’organisation différents dans chaque organisation à laquelle ils appartiennent. Pour en savoir plus, consultez [Rôles d’organisation](/docs/fr-ca/manage-users/organizations/organization-roles).

<div id="prerequisites">
  ## Prérequis
</div>

* Pour que le contrôle d’accès basé sur les rôles (RBAC) fonctionne correctement, vous devez l’activer pour votre API à l’aide du Dashboard ou de la Management API. La fonctionnalité Authorization Core est différente de l’Authorization Extension. Pour comparer les deux, consultez [Authorization Core vs. Authorization Extension](/docs/fr-ca/manage-users/access-control/authorization-core-vs-authorization-extension).
* [Configurer une API](/docs/fr-ca/get-started/auth0-overview/set-up-apis) dans l’<Tooltip tip="Auth0 Dashboard : principal produit d’Auth0 pour configurer vos services." cta="Voir le glossaire" href="/docs/fr-ca/glossary?term=Auth0+Dashboard">Auth0 Dashboard</Tooltip>.
* Les permissions proviennent de valeurs prédéfinies. Si votre liste de permissions est vide, vous devez [ajouter des permissions](/docs/fr-ca/get-started/apis/add-api-permissions) à votre API.

<div id="create-a-tenant-role">
  ## Créer un rôle de tenant
</div>

Les rôles de tenant s’appliquent à l’ensemble du tenant et peuvent être attribués à n’importe quel utilisateur, qu’il appartienne ou non à une organisation.

<Tabs>
  <Tab title="Auth0 Dashboard">
    1. Accédez à [Dashboard &gt; User Management &gt; Roles](https://manage.auth0.com/#/roles) et sélectionnez **Create Role**.
    2. Donnez un nom au rôle et ajoutez une description, puis sélectionnez **Create**.
  </Tab>

  <Tab title="Management API">
    Effectuez un appel `POST` au [point de terminaison Create Role](/docs/fr-ca/api/management/v2#!/Roles/post_roles). Veillez à remplacer les valeurs de remplacement `MGMT_API_ACCESS_TOKEN`, `ROLE_NAME` et `ROLE_DESC` par votre <Tooltip tip="Jeton d’accès : identifiant d’autorisation, sous la forme d’une chaîne opaque ou d’un JWT, utilisé pour accéder à une API." cta="Voir le glossaire" href="/docs/fr-ca/glossary?term=access+token">jeton d’accès</Tooltip> de l’API de gestion, le nom du rôle et la description du rôle, respectivement.

    <Callout icon="file-lines" color="#0EA5E9" iconType="regular">Vous utilisez l’Auth0 CLI? Si ce n’est pas déjà fait, [configurez et authentifiez votre session CLI](/docs/fr-ca/deploy-monitor/auth0-cli) avant d’exécuter cette commande.</Callout>

<div id="create-an-organization-role">
  ## Créer un rôle d’organisation
</div>

Vous pouvez créer des rôles d’organisation à partir de la vue de gestion de l’organisation. Les administrateurs de tenant peuvent créer jusqu’à 350 rôles d’organisation par organisation.

<Tabs>
  <Tab title="Auth0 Dashboard">
    1. Accédez à [Dashboard &gt; Organizations](https://manage.auth0.com/#/organizations) et sélectionnez l’organisation.
    2. Sélectionnez l’onglet **Roles**, puis **Create Role**.
    3. Saisissez un nom et une description pour le rôle, puis sélectionnez **Create**.
  </Tab>

  <Tab title="Management API">
    Effectuez une requête `POST` vers le [endpoint Create Role](/docs/fr-ca/api/management/v2#!/Roles/post_roles). Définissez `type` à `"organization"` et `owner_id` à l’ID de l’organisation. Veillez à remplacer les valeurs de l’espace réservé `MGMT_API_ACCESS_TOKEN`, `ROLE_NAME`, `ROLE_DESC` et `ORG_ID` par votre <Tooltip tip="Jeton d’accès : justificatif d’autorisation, sous la forme d’une chaîne opaque ou d’un JWT, utilisé pour accéder à une API." cta="Voir le glossaire" href="/docs/fr-ca/glossary?term=access+token">jeton d’accès</Tooltip> pour la Management API, le nom du rôle, la description du rôle et l’ID de l’organisation, respectivement.

    <Tabs>
      <Tab title="Auth0 CLI">
        ```bash
        auth0 api post "roles" \
          --data '{ "name": "ROLE_NAME", "description": "ROLE_DESC", "type": "organization", "owner_id": "ORG_ID" }'
        ```
      </Tab>

      <Tab title="cURL">
        ```bash cURL
        curl --request POST \
          --url 'https://{yourDomain}/api/v2/roles' \
          --header 'authorization: Bearer MGMT_API_ACCESS_TOKEN' \
          --header 'cache-control: no-cache' \
          --header 'content-type: application/json' \
          --data '{ "name": "ROLE_NAME", "description": "ROLE_DESC", "type": "organization", "owner_id": "ORG_ID" }'
        ```
      </Tab>
    </Tabs>

    | **Valeur**              | **Description**                                                                                       |
    | ----------------------- | ----------------------------------------------------------------------------------------------------- |
    | `MGMT_API_ACCESS_TOKEN` | [Jeton d’accès pour la Management API](/docs/fr-ca/api/management/v2/tokens) avec la portée `create:roles`. |
    | `ROLE_NAME`             | Nom du rôle d’organisation à créer. Il doit être unique au sein de l’organisation.                    |
    | `ROLE_DESC`             | Description conviviale du rôle.                                                                       |
    | `ORG_ID`                | ID de l’organisation dans laquelle créer le rôle.                                                     |

    La réponse comprend `type: "organization"` et `owner_id`, ce qui confirme que le rôle est associé à l’organisation.
  </Tab>
</Tabs>
