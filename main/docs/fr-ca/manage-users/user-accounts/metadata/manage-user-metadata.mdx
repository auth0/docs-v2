Vous pouvez accéder aux champs `user_metadata` et `app_metadata` des profils utilisateur et les définir à l’aide de diverses méthodes, selon votre cas d’utilisation.

<Tabs>
  <Tab title="Management API">
    Lorsque vous créez un nouvel utilisateur à l’aide du [terminal Create a User de Management API](/docs/fr-ca/api/management/v2/users/post-users) (`POST /users`), vous pouvez définir ses métadonnées en précisant les paramètres de corps `user_metadata` et `app_metadata`.

    <Accordion title="Exemple : créer un nouvel utilisateur avec des métadonnées">
      Pour créer un utilisateur avec les renseignements de profil suivants :

      ```json
      {
          "email": "jane.doe@example.com",
          "user_metadata": {
              "hobby": "surfing"
          },
          "app_metadata": {
              "plan": "full"
          }
      }
      ```

      Effectuez l’appel `POST` suivant au terminal [`/post_users`](https://auth0.com/docs/api/management/v2#!/Users/post_users) de <Tooltip tip="Management API : un produit permettant aux clients d’effectuer des tâches administratives." cta="Voir le glossaire" href="/docs/fr-ca/glossary?term=Management+API">Management API</Tooltip> pour créer l’utilisateur et définir les valeurs des propriétés :

      <Callout icon="file-lines" color="#0EA5E9" iconType="regular">Vous utilisez l’interface de ligne de commande (CLI) Auth0? Si ce n’est pas déjà fait, [configurez et authentifiez votre session CLI](/docs/fr-ca/deploy-monitor/auth0-cli) avant d’exécuter cette commande.</Callout>

      <AuthCodeGroup>
        ```bash Auth0 CLI
        auth0 api post "users" \
          --data '{"email": "jane.doe@example.com", "user_metadata": {"hobby": "surfing"}, "app_metadata": {"plan": "full"}}'
        ```

        ```bash cURL
        curl --request POST \
          --url 'https://{yourDomain}/api/v2/users' \
          --header 'authorization: Bearer MGMT_API_ACCESS_TOKEN' \
          --header 'content-type: application/json' \
          --data '{"email": "jane.doe@example.com", "user_metadata": {"hobby": "surfing"}, "app_metadata": {"plan": "full"}}'
        ```

        ```csharp C#

    Lorsque vous mettez à jour les métadonnées d&#39;un utilisateur existant, seules les propriétés de premier niveau sont fusionnées dans l&#39;objet. Toutes les propriétés des niveaux inférieurs sont remplacées.

    <Accordion title="Exemple : mettre à jour les sous-propriétés des métadonnées">
      Par exemple, pour ajouter l&#39;adresse professionnelle d&#39;un utilisateur comme propriété interne supplémentaire, vous devriez inclure tout le contenu de la propriété `addresses`. Comme l&#39;objet `addresses` est une propriété de niveau racine, il sera fusionné dans l&#39;objet JSON final qui représente l&#39;utilisateur, mais ce ne sera pas le cas de ses sous-propriétés.

      {
        "user_metadata": {
          "addresses": {
            "home": "123 Main Street, Anytown, ST 12345",
            "work": "100 Industrial Way, Anytown, ST 12345"
          }
        }
      }
      ```

    Pour supprimer une clé de métadonnées, effectuez un appel `PATCH` en définissant la valeur de cette clé à `null` (par exemple, `{ "user_metadata": {"color": null}}`).

    Pour supprimer entièrement les métadonnées d’utilisateur ou d’application, effectuez un appel `PATCH` et attribuez un objet vide aux métadonnées elles-mêmes (par exemple, `{ "user_metadata": {} }`).

  <Tab title="Action `post-login`">
    Vous pouvez configurer un déclencheur `post-login` pour modifier `user_metadata` et `app_metadata` dans le cadre du flux de connexion d’un utilisateur.

    Les déclencheurs post-connexion sont utiles pour des tâches comme le stockage de données propres à l’application dans le profil utilisateur, la capture des journaux d’opérations de l’utilisateur, le mappage des attributs <Tooltip tip="Security Assertion Markup Language (SAML) : protocole normalisé permettant à deux parties d’échanger des informations d’authentification sans mot de passe." cta="Voir le glossaire" href="/docs/fr-ca/glossary?term=SAML">SAML</Tooltip> vers le champ de métadonnées, ou encore la mise en cache, dans le profil utilisateur, des valeurs d’opérations coûteuses afin de les réutiliser lors des connexions ultérieures.

    L’objet `api` de `post-login` fournit des opérations courantes que vous pouvez effectuer dans ce déclencheur. Pour gérer les métadonnées d’utilisateur, nous utiliserons les méthodes `api.user.setAppMetadata` et `api.user.setUserMetadata`. Par exemple, pour éviter qu’un comportement ne s’exécute plus d’une fois pour un utilisateur donné, vous pourriez utiliser une Action comme celle-ci :

    ```js
    exports.onExecutePostLogin = async (event, api) => {
      if (event.user.app_metadata.didAnExpensiveTask) {
        console.log(`Skipping the expensive task because it already occurred for ${event.user.email}.`);

        return;
      }
      // effectuer une tâche coûteuse
      api.user.setAppMetadata("didAnExpensiveTask", true);
    };
    ```

    Ici, nous avons ajouté une vérification au début de l’Action afin de déterminer si la tâche coûteuse a déjà été effectuée pour cet utilisateur. Si le champ de métadonnées existe, nous quittons la fonction.

    À la fin de l’Action, nous appelons `api.user.setAppMetadata` pour indiquer que nous souhaitons stocker des métadonnées dans l’objet utilisateur. À la fin de l’exécution de chaque déclencheur, les Actions mettent à jour le profil utilisateur en une seule opération. Si plusieurs appels à `setUserMetadata` sont effectués, même s’ils proviennent d’actions différentes au sein du même flux, les Actions ne mettront à jour le profil utilisateur qu’une seule fois, soit à la fin de l’exécution du déclencheur.

    <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
      Plusieurs appels à `setUserMetadata` ou à `setAppMetadata` seront regroupés en une seule mise à jour du profil utilisateur à la fin de l’exécution du déclencheur, même s’ils sont effectués par des Actions différentes.
    </Callout>

    Dans le cas d’une [redirection déclenchée avec `api.redirect.sendUserTo()`](/docs/fr-ca/customize/actions/redirect-with-actions), toutes les mises à jour en attente des métadonnées d’utilisateur ou d’application seront appliquées au profil utilisateur avant que l’utilisateur ne soit redirigé vers le site externe.
  </Tab>

  <Tab title="Verrouiller">
    Vous pouvez utiliser la [bibliothèque Lock](/docs/fr-ca/libraries/lock) pour définir, ajouter, lire et mettre à jour les `user_metadata.` Vous pouvez lire les propriétés `user_metadata` de l&#39;utilisateur de la même façon que vous liriez n&#39;importe quelle autre propriété du profil utilisateur. Par exemple, l&#39;extrait de code suivant récupère la valeur associée à `user_metadata.hobby` et l&#39;attribue à un élément de la page :

    ```javascript
    // Utiliser l'accessToken obtenu lors de l'authentification pour appeler getUserInfo
    lock.getUserInfo(accessToken, function(error, profile) {
      if (!error) {
        document.getElementById('hobby').textContent = profile.user_metadata.hobby;
      }
    });
    ```

    Vous pouvez utiliser `additionalSignUpFields` pour ajouter des champs personnalisés aux formulaires d’inscription des utilisateurs. Lorsqu’un utilisateur saisit des données dans un champ personnalisé, Auth0 enregistre les valeurs saisies dans le `user_metadata` de cet utilisateur. Pour en savoir plus sur l’ajout de `user_metadata` lors de l’inscription, consultez [Champs d’inscription supplémentaires](/docs/fr-ca/libraries/lock/lock-configuration#additionalsignupfields-array-).
  </Tab>

## Lecture des métadonnées {#read-metadata}

    Vous pouvez lire les métadonnées à l’aide de règles avec la <Tooltip tip="Management API : un produit permettant aux clients d’effectuer des tâches administratives." cta="Voir le glossaire" href="/docs/fr-ca/glossary?term=Management+API">Management API</Tooltip>. Vous pouvez également rechercher des renseignements liés au profil dans `user_metadata`, par exemple :

    * `name`
    * `nickname`
    * `given_name`
    * `family_name`

    Par exemple, supposons que les métadonnées suivantes sont stockées pour un utilisateur dont l&#39;adresse courriel est `jane.doe@example.com`\u00a0:

    ```json
    {
        "email": "jane.doe@example.com",
        "user_metadata": {
            "hobby": "surfing"
        },
        "app_metadata": {
            "plan": "full"
        }
    }
    ```

    À l’aide de l’exemple de métadonnées ci-dessus, vous pouvez faire référence à des éléments précis de l’ensemble de données dans les [Rules Auth0](/docs/fr-ca/customize/rules) ou au moyen d’un appel à la [Management API](/docs/fr-ca/manage-users/user-accounts/metadata), comme suit :

    ```js
    console.log(user.email); // "jane.doe@example.com"
    console.log(user.user_metadata.hobby); // "surfing"
    console.log(user.app_metadata.plan); // "full"
    ```

    N’importe quel extrait JSON valide peut servir de métadonnées. Par défaut, `user.app_metadata` est `Undefined`.

    <Accordion title="Exemple : condition fondée sur les métadonnées">
      Vous pouvez prendre une décision en fonction des rôles de l&#39;utilisateur :

      ```javascript
      function(user, context, callback){
        user.app_metadata = user.app_metadata || {};
        if (user.app_metadata.roles.indexOf('writer')){
          // code à exécuter
        }
      }
      ```

      Vous pouvez prendre des décisions en fonction de préférences précises, comme une préférence de couleur :

      ```javascript
      function(user, context, callback){
        user.user_metadata = user.user_metadata || {};
        if (user.user_metadata.preferences.color === 'black'){
          // code à exécuter
        }
        ...
      }
      ```
    </Accordion>

### Lecture des métadonnées de l&#39;application (clientMetadata) {#read-application-metadata-clientmetadata}

    Les métadonnées d’application (`clientMetadata`) sont une propriété facultative de premier niveau de l’objet `context`. Pour les applications existantes, cette propriété n’aura aucune valeur.

    ```javascript
    function(user, context, callback){
      context.clientMetadata = context.clientMetadata || {};
      if (context.clientMetadata.usersuppliedkey1 === 'black'){
        // ce code ne serait pas exécuté pour l'utilisateur
      }
      ...
    }
    ```

## Mettre à jour les métadonnées {#update-metadata}

    Vous pouvez utiliser des Rules pour associer les attributs SAML qu’Auth0 reçoit de l’IdP à `user_metadata` ou à `app_metadata`.

### Mettre à jour les métadonnées de l&#39;application {#update-app-metadata}

    Pour attribuer un rôle d&#39;administrateur à l&#39;utilisateur\u00a0:

    ```javascript
    function(user, context, callback){
      user.app_metadata = user.app_metadata || {};
      // mettre à jour les app_metadata qui feront partie de la réponse
      user.app_metadata.roles = user.app_metadata.roles || [];
      user.app_metadata.roles.push('administrator');

      // rendre persistante la mise à jour des app_metadata
      auth0.users.updateAppMetadata(user.user_id, user.app_metadata)
        .then(function(){
          callback(null, user, context);
        })
        .catch(function(err){
          callback(err);
        });
    }
    ```

    On obtient ainsi la représentation JSON suivante des détails du profil utilisateur :

    ```json
    {
      "user_id": "jdoe",
      "email": "john.doe@example.com",
      "app_metadata": {
        "roles": [ "writer", "administrator" ]
      },
      "user_metadata": {
        "preferences": {
          "color": "blue"
        }
      }
    }
    ```

### Mettre à jour les métadonnées d’utilisateur {#update-user-metadata}

    Pour ajouter la préférence `fontSize` de l&#39;utilisateur au profil utilisateur :

    ```javascript
    function(user, context, callback){
      user.user_metadata = user.user_metadata || {};
      // mettre à jour les user_metadata qui seront incluses dans la réponse
      user.user_metadata.preferences = user.user_metadata.preferences || {};
      user.user_metadata.preferences.fontSize = 12;

      // enregistrer la mise à jour des user_metadata
      auth0.users.updateUserMetadata(user.user_id, user.user_metadata)
        .then(function(){
          callback(null, user, context);
        })
        .catch(function(err){
          callback(err);
        });
    }
    ```

    On obtient ainsi la représentation JSON suivante des détails du profil utilisateur :

    ```json
    {
      "user_id": "jdoe",
      "email": "john.doe@example.com",
      "app_metadata": {
        "roles": [ "writer" ]
      },
      "user_metadata": {
        "preferences": {
          "color": "blue",
          "fontSize": 12
        }
      }
    }
    ```

### Mettre à jour simultanément les métadonnées d’application et les métadonnées d’utilisateur {#update-app-and-user-metadata-simultaneously}

    Pour réduire le temps de traitement de la Rule, vous pouvez mettre à jour `app_metadata` et `user_metadata` dans la même Rule :

    ```javascript expandable
    function(user, context, callback){

      var q = require('q');

      user.app_metadata = user.app_metadata || {};
      user.user_metadata = user.user_metadata || {};
      // mettre à jour les user_metadata qui feront partie de la réponse
      user.user_metadata.preferences = user.user_metadata.preferences || {};
      user.user_metadata.preferences.fontSize = 12;

      // mettre à jour les app_metadata qui feront partie de la réponse
      user.app_metadata.roles = user.app_metadata.roles || [];
      user.app_metadata.roles.push('admin');

      // conserver la mise à jour des app_metadata
      var appMetadataPromise  = auth0.users.updateAppMetadata(user.user_id, user.app_metadata);

      // conserver la mise à jour des user_metadata
      var userMetadataPromise = auth0.users.updateUserMetadata(user.user_id, user.user_metadata);

      // utiliser la bibliothèque q pour attendre que toutes les promesses soient terminées
      q.all([userMetadataPromise, appMetadataPromise])
        .then(function(){
          callback(null, user, context);
        })
        .catch(function(err){
          callback(err);
        });
    }
    ```

    On obtient ainsi la représentation JSON suivante des détails du profil utilisateur :

    ```json
    {
      "user_id": "jdoe",
      "email": "john.doe@example.com",
      "app_metadata": {
        "roles": [ "writer", "admin" ]
      },
      "user_metadata": {
        "preferences": {
          "color": "blue",
          "fontSize": 12
        }
      }
    }
    ```

## Supprimer les métadonnées {#delete-metadata}

### Supprimer les propriétés et les valeurs des métadonnées de l&#39;application {#delete-app-metadata-properties-and-values}

    Pour supprimer une propriété, définissez sa valeur à `null`.

#### Exemple de suppression des rôles d’un utilisateur {#delete-users-roles-example}

    Pour supprimer les rôles de l&#39;utilisateur, utilisez l&#39;exemple de Rule suivant :

    ```javascript
    function(user, context, callback){
      user.app_metadata = user.app_metadata || {};
      // mettre à jour les app_metadata qui seront incluses dans la réponse
      user.app_metadata.roles = null;

      // enregistrer de façon persistante la mise à jour des app_metadata
      auth0.users.updateAppMetadata(user.user_id, user.app_metadata)
        .then(function(){
          callback(null, user, context);
        })
        .catch(function(err){
          callback(err);
        });
    }
    ```

    On obtient ainsi la représentation JSON suivante du profil utilisateur :

    ```json
    {
      "user_id": "jdoe",
      "email": "john.doe@example.com",
      "app_metadata": { },
      "user_metadata": {
        "preferences": {
          "color": "blue"
        }
      }
    }
    ```

#### Exemple de suppression d’une seule valeur de propriété {#delete-single-property-value-example}

    Pour supprimer une seule valeur d&#39;une propriété, retirez cette valeur précise. Par exemple, pour retirer le rôle `writer` du profil utilisateur :

    ```javascript
    function(user, context, callback){
      user.app_metadata = user.app_metadata || {};
      user.app_metadata.roles = user.app_metadata.roles || [];

      var index = user.app_metadata.roles.indexOf('writer');

      if (index !== -1){
        // mettre à jour les app_metadata qui seront incluses dans la réponse
        user.app_metadata.roles.splice(index, 1);
      }

      // rendre persistante la mise à jour des app_metadata
      auth0.users.updateAppMetadata(user.user_id, user.app_metadata)
        .then(function(){
          callback(null, user, context);
        })
        .catch(function(err){
          callback(err);
        });
    }
    ```

    On obtient ainsi la représentation JSON suivante du profil utilisateur :

    ```json
    {
      "user_id": "google-oauth2|1234",
      "email": "john.doe@gmail.com",
      "app_metadata": {
        "roles": [ ]
      },
      "user_metadata": {
        "preferences": {
          "color": "blue"
        }
      }
    }
    ```

    La propriété `roles` existe toujours, mais ne contient aucune valeur.

### Supprimer des propriétés et des valeurs de métadonnées d’utilisateur {#delete-user-metadata-properties-and-values}

    Pour supprimer la préférence de couleur de l&#39;utilisateur :

    ```javascript
    function(user, context, callback){
      user.user_metadata = user.user_metadata || {};
      // mettre à jour les user_metadata qui feront partie de la réponse
      user.user_metadata.preferences = user.user_metadata.preferences || {};
      delete user.user_metadata.preferences.color;

      // rendre persistante la mise à jour des user_metadata
      auth0.users.updateUserMetadata(user.user_id, user.user_metadata)
        .then(function(){
          callback(null, user, context);
        })
        .catch(function(err){
          callback(err);
      });
    }
    ```

    On obtient ainsi la représentation JSON suivante des détails du profil utilisateur :

    ```json
    {
      "user_id": "jdoe",
      "email": "john.doe@example.com",
      "app_metadata": {
        "roles": [ "writer" ]
      },
      "user_metadata": {
        "preferences": { }
      }
    }
    ```
