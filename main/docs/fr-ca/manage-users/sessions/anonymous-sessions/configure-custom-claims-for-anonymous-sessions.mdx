Lorsque vos serveurs de ressources ont besoin de renseignements supplémentaires sur un utilisateur, mais que vous ne transmettez qu’un [jeton d’accès](/docs/fr-ca/secure/tokens/access-tokens), vous pouvez enrichir celui-ci de [demandes personnalisées](/docs/fr-ca/secure/tokens/json-web-tokens/create-custom-claims) afin d’y stocker des données additionnelles.

Une façon courante de définir une demande personnalisée consiste à appeler [`api.accessToken.setCustomClaim()`](/docs/fr-ca/actions/reference/credentials-exchange/credentials-exchange-api-object#api-accesstoken-setcustomclaim-key-value) dans une Action [`post-login`](/docs/fr-ca/customize/actions/explore-triggers/post-login). Toutefois, dans un contexte de [sessions anonymes](/docs/fr-ca/manage-users/sessions/anonymous-sessions), il n’y a pas de connexion, et donc aucune exécution d’Action `post-login`. Il devient alors impossible d’ajouter des demandes personnalisées au jeton d’accès de la manière habituelle, et les API qui s’attendent à ces demandes ne peuvent pas les lire.

Pour pallier ce problème, Auth0 propose le mappage des demandes, soit une correspondance directe entre les métadonnées d’une session anonyme et les jetons d’accès émis pour celle-ci. Par exemple, pour une session qui contient ceci :

```json
{
  "user_id": "anon@1234-5678-90",
  "session_id": "sess_456",
  "metadata": {
    "language": "EN",
    "country": "US",
    "purchase": "P0123"
  }
}
```

Vous pouvez configurer votre API pour qu&#39;elle lise la valeur `language` de chaque nouveau jeton d&#39;accès anonyme qu&#39;elle crée et qu&#39;elle l&#39;inclue sous forme de demande personnalisée nommée `lang`.

## Configurer le mappage des demandes {#configure-claims-mapping}

Pour configurer le mappage des demandes des sessions anonymes, vous pouvez utiliser le [Auth0 Dashboard](/docs/fr-ca/get-started/auth0-overview/dashboard) ou la [Management API](/docs/fr-ca/api/management/v2).

<Tabs>
  <Tab title="Auth0 Dashboard">
    1. Accédez à [**Dashboard &gt; Applications &gt; APIs**](https://manage.auth0.com/#/apis), puis sélectionnez l&#39;API dont vous voulez configurer les demandes.

    2. Sélectionnez l&#39;onglet **Claim Mapping**.

       ![La page de mappage des demandes de l'application dans le Auth0 Dashboard](/docs/images/sessions/anonymous_sessions/anonymous_sessions_claim_mapping.png)

    3. Sous **Add a claim**, saisissez un **Name** de demande (par exemple, `lang`) et une **Expression** qui renvoie à une valeur sous `anonymous_session.metadata.*` (par exemple, `anonymous_session.metadata.language`), puis sélectionnez **Add**.

    4. Pour modifier une demande existante, sélectionnez l&#39;icône de crayon à côté de celle-ci. Pour en supprimer une, sélectionnez l&#39;icône de corbeille.
  </Tab>

  <Tab title="Management API">
    Pour configurer le mappage des demandes de votre API, envoyez une requête `PATCH` au terminal [`/api/v2/resource-servers/{id}`](/docs/fr-ca/api/management/v2/resource-servers/patch-resource-servers-by-id) :

    ```json
    {
      "access_token": {
        "claims_mapping": {
          "custom_claims": [
            {
              "name": "tier",
              "expression": "anonymous_session.metadata.tier"
            },
            {
              "name": "lang",
              "expression": "anonymous_session.metadata.language"
            }
          ]
        }
      }
    }
    ```

    Chaque entrée de `custom_claims` associe le `name` d&#39;une demande du jeton d&#39;accès émis à une `expression` qui lit une valeur de la session anonyme, comme `anonymous_session.metadata.<key>`.

    <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
      La requête `PATCH` remplace la liste `custom_claims` au complet; vous devez donc y inclure toutes les demandes que vous voulez conserver. Faites précéder votre `PATCH` d&#39;une requête `GET` pour récupérer les demandes existantes, apportez les modifications voulues, puis renvoyez l&#39;objet complet dans la requête `PATCH`.
    </Callout>
  </Tab>
</Tabs>
