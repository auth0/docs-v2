<Warning>
  La date de fin de vie (EOL) de Rules et Hooks sera le **18 novembre 2026**, et ils ne sont plus disponibles pour les nouveaux tenants créés à compter du **16 octobre 2023**. Les tenants existants ayant des Hooks actifs conserveront l’accès au produit Hooks jusqu’à la fin de vie.

  Nous vous recommandons fortement d’utiliser Actions pour étendre Auth0. Avec Actions, vous avez accès à de riches informations de typage, à une documentation intégrée et à des packages `npm` publics, et vous pouvez connecter des intégrations externes qui améliorent votre expérience globale d’extensibilité. Pour en savoir plus sur ce que permettent les Actions, consultez [Comprendre le fonctionnement des Auth0 Actions](/docs/fr-ca/customize/actions/actions-overview).

  Pour vous aider dans votre migration, nous proposons des guides qui vous aideront à [passer de Rules à Actions](/docs/fr-ca/customize/actions/migrate/migrate-from-rules-to-actions) et à [passer de Hooks à Actions](/docs/fr-ca/customize/actions/migrate/migrate-from-hooks-to-actions). Nous avons également une page dédiée, [Move to Actions](https://auth0.com/extensibility/movetoactions), qui présente des comparaisons de fonctionnalités, [une démonstration d’Actions](https://www.youtube.com/watch?v=UesFSY1klrI) et d’autres ressources pour vous accompagner dans votre démarche de migration.

  Pour en savoir plus sur la dépréciation de Rules et Hooks, consultez notre billet de blogue : [Preparing for Rules and Hooks End of Life](https://auth0.com/blog/preparing-for-rules-and-hooks-end-of-life/).
</Warning>

<Warning>
  Comme nous prévoyons supprimer les fonctions Rules et Hooks en 2026, vous ne devriez créer de nouvelles Rules ou de nouveaux Hooks que dans votre environnement de développement, et uniquement pour tester la migration vers Actions.

  Pour savoir comment migrer vos Rules vers Actions, consultez [passer de Rules à Actions](/docs/fr-ca/customize/actions/migrate/migrate-from-rules-to-actions). Pour savoir comment migrer vos Hooks vers Actions, consultez [passer de Hooks à Actions](/docs/fr-ca/customize/actions/migrate/migrate-from-hooks-to-actions).
</Warning>

Vous pouvez activer ou désactiver les Hooks à l’aide du Dashboard ou de <Tooltip tip="Management API : une API qui permet aux clients d’effectuer des tâches administratives." cta="Voir le glossaire" href="/docs/fr-ca/glossary?term=Management+API">Management API</Tooltip>.

<Warning>
  Bien que vous puissiez créer plusieurs hooks pour un point d’extensibilité donné, chaque point d’extensibilité ne peut avoir qu’un seul hook activé à la fois. Tous les hooks supplémentaires que vous créez pour ce point d’extensibilité sont automatiquement désactivés; vous devez donc les activer explicitement. Le hook activé sera exécuté pour toutes les applications et API.
</Warning>

<Warning>
  Lors de la création de nouveaux hooks, Auth0 active automatiquement le premier Hook que vous créez pour un point d’extensibilité. Tous les hooks supplémentaires que vous créez pour ce point d’extensibilité sont automatiquement désactivés; vous devez donc les activer explicitement.
</Warning>

<div id="use-the-dashboard">
  ## Utiliser le Dashboard
</div>

1. Accédez à [Auth0 Dashboard &gt; Auth Pipeline &gt; Hooks](https://manage.auth0.com/#/) et repérez le point d’extensibilité pour lequel vous voulez activer ou désactiver un Hook.
2. Cliquez sur la liste déroulante située juste sous le nom et la description du point d’extensibilité.

   <Frame>![Sélection du Hook Auth0](/docs/images/cdy7uua7fh8z/2LCBPLtrsjmmJYxCGfWquT/74b232fd96aa179c89f01e46d2e91ce3/dashboard-hooks-list.png)</Frame>
3. Sélectionnez le Hook que vous voulez activer, puis confirmez. Si vous voulez désactiver tous les Hooks, sélectionnez `None`.

Un point vert apparaîtra à côté du nom de chaque Hook activé.

<div id="use-the-management-api">
  ## Utiliser la Management API
</div>

Effectuez une requête `PATCH` au [point de terminaison Update a Hook](https://auth0.com/docs/api/management/v2/#!/Hooks/patch_hooks_by_id). Assurez-vous de remplacer les valeurs de l’espace réservé `HOOK_ID` et `MGMT_API_ACCESS_TOKEN` par l’ID de votre Hook et votre <Tooltip tip="Jeton d’accès : information d’identification, sous la forme d’une chaîne opaque ou d’un JWT, utilisée pour accéder à une API." cta="Voir le glossaire" href="/docs/fr-ca/glossary?term=Access+Token">jeton d’accès</Tooltip> de la Management API, respectivement.

<Callout icon="file-lines" color="#0EA5E9" iconType="regular">Vous utilisez l’Auth0 CLI ? Si ce n’est pas déjà fait, [configurez et authentifiez votre session CLI](/docs/fr-ca/deploy-monitor/auth0-cli) avant d’exécuter cette commande.</Callout>

  ```bash Auth0 CLI
  auth0 api patch "hooks/HOOK_ID" \
  ```

  ```bash cURL
    --header 'content-type: application/json' \
    --data '{ "enabled": "true" }'
  ```

  ```go Go
  import (

  	req.Header.Add("cache-control", "no-cache")

  	defer res.Body.Close()
  	body, _ := ioutil.ReadAll(res.Body)

  }
  ```

| Valeur                  | Description                                                                                                                                                                                                     |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HOOK_ID`               | ID du hook à mettre à jour.                                                                                                                                                                                     |
| `MGMT_API_ACCESS_TOKEN` | Jeton d’accès pour la Management API avec la [portée](/docs/fr-ca/glossary?term=scope) `create:hooks`. Pour en savoir plus, consultez [Management API Access Tokens](https://auth0.com/docs/api/management/v2/tokens). |

<Callout icon="file-lines" color="#0EA5E9" iconType="regular">
  La propriété `enabled` indique si la règle est activée (`true`) ou désactivée (`false`).
</Callout>
