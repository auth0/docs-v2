## Pour commencer {#get-started}

Suivez le Quickstart pour créer un Action Module et l’utiliser dans une Action afin d’envoyer des logs à un service externe.

<Steps titleSize="h3">
  <Step title="Créer un module d’action">
    Pour utiliser un Action Module dans une Action précise, vous devez d’abord créer l’Action Module, puis l’ajouter ou l’utiliser dans l’Action.

    <Tabs>
      <Tab title="Dashboard">
        1. Accédez à [Auth0 Dashboard &gt; Actions &gt; Library](https://manage.auth0.com/#/actions/library), puis sélectionnez **Modules**.
        2. Sélectionnez **Create Module**.
        3. Entrez un **Name**.
        4. Sélectionnez **Create**.

        <Frame>![Actions Modules - Nouvel Action Module](/docs/images/customize/actions/modules/actions-modules-new-module.png)</Frame>
      </Tab>

      <Tab title="Management API">
        1. [Obtenez un jeton d’accès de la Management API](/docs/fr-ca/secure/tokens/access-tokens/management-api-access-tokens) avec la permission `create:actions`.
        2. Appelez [Create an Actions Module](/docs/fr-ca/api/management/v2/actions/post-action-module) :

        ```shell
        curl -L 'https://{yourDomain}/api/v2/actions/modules' \
          -H 'Content-Type: application/json' \
          -H 'Authorization: Bearer {yourMgmtApiAccessToken}' \
          -d '{
            "name": "logger",
            "code": "module.exports = {};",
            "api_version": "1",
            "publish": false
          }'
        ```

        Auth0 retourne le nouvel Action Module, y compris son `id`, que vous utiliserez pour référencer le module aux étapes suivantes.
      </Tab>

      <Tab title="Auth0 CLI">
        <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
          Les Actions Modules ne sont pas exposés nativement par l’ensemble de commandes `auth0-cli`; utilisez donc [`auth0 api`](https://auth0.github.io/auth0-cli/auth0_api.html) pour appeler directement la Management API. Certains appels nécessitent des permissions supplémentaires — au besoin, exécutez d’abord `auth0 login --scopes create:actions,read:actions,update:actions`.
        </Callout>

        Appelez [Create an Actions Module](/docs/fr-ca/api/management/v2/actions/post-action-module) avec `auth0 api` :

        ```shell
        auth0 api post actions/modules --data '{
          "name": "logger",
          "code": "module.exports = {};",
          "api_version": "1",
          "publish": false
        }'
        ```

        Auth0 retourne le nouvel Action Module, y compris son `id`, que vous utiliserez pour référencer le module aux étapes suivantes.
      </Tab>

      <Tab title="Terraform">
        <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
          Consultez la documentation de la ressource [`auth0_action_module`](https://registry.terraform.io/providers/auth0/auth0/latest/docs/resources/action_module) pour en savoir plus.
        </Callout>

        1. Ajoutez la ressource suivante à un fichier `.tf`, en référençant le code du module à partir d’un fichier :

        ```terraform title="action-modules/logger.tf"
        resource "auth0_action_module" "logger" {
          name = "logger"
          code = file("${path.module}/action-modules/logger/code.js")
        }
        ```

        2. Créez le fichier de code du module à l’emplacement `action-modules/logger/code.js` :

        ```javascript title="action-modules/logger/code.js"
        module.exports = {};
        ```

        3. Exécutez `terraform apply`.

        Vous enrichirez le fichier de code et cette ressource avec des secrets aux étapes suivantes.
      </Tab>

      <Tab title="Auth0 Deploy CLI">
        <Tabs>
          <Tab title="YAML">
            1. Créez le fichier de code du module à l’emplacement `action-modules/logger/code.js` :

            ```javascript title="action-modules/logger/code.js"
            module.exports = {};
            ```

            2. Ajoutez une entrée `actionModules` dans `tenant.yaml` :

            ```yaml title="tenant.yaml"
            actionModules:
              - name: logger
                code: ./action-modules/logger/code.js
            ```

            3. Déployez la configuration :

            ```shell
            a0deploy import -c=config.json --input_file=tenant.yaml
            ```
          </Tab>

          <Tab title="Directory (JSON)">
            1. Créez le fichier de configuration du module à l’emplacement `action-modules/logger.json` :

            ```json title="action-modules/logger.json"
            {
              "name": "logger",
              "code": "./action-modules/logger/code.js"
            }
            ```

            2. Créez le fichier de code du module à l’emplacement `action-modules/logger/code.js` :

            ```javascript title="action-modules/logger/code.js"
            module.exports = {};
            ```

            3. Déployez la configuration :

            ```shell
            a0deploy import -c=config.json --input_file=local.
            ```
          </Tab>
        </Tabs>
      </Tab>
    </Tabs>
  </Step>

  <Step title="Ajouter un secret">
    Chaque module d’action peut contenir des paires clé-valeur secrètes. Utilisez-les pour stocker des renseignements sensibles, comme des clés API, des certificats et des valeurs qui peuvent varier d’un environnement à l’autre.

    <Tabs>
      <Tab title="Dashboard">
        Ensuite, enregistrez l’URL du service externe comme Secret.

        1. Sélectionnez l’icône **<svg style={{ display: 'inline' }} width="20" height="20" viewBox="0 0 24 24" fill="currentColor" xmlns="http://www.w3.org/2000/svg" class="sc-kJNqSH"><path fill-rule="evenodd" clip-rule="evenodd" d="M19.573 2.06l1.409 1.42-1.192 1.182L22.65 7.5l-4.756 4.72-2.86-2.838-2.783 2.764a6.196 6.196 0 011.196 3.63 6.172 6.172 0 01-1.832 4.41 6.277 6.277 0 01-8.853-.03l-.007-.008A6.183 6.183 0 011 15.782a6.184 6.184 0 011.831-4.335 6.271 6.271 0 017.987-.696l8.755-8.691zm-9.335 10.798l-.045-.043a4.264 4.264 0 00-2.987-1.182 4.262 4.262 0 00-2.966 1.233A4.184 4.184 0 003 15.8a4.183 4.183 0 001.185 2.95 4.276 4.276 0 006.022.016 4.2 4.2 0 001.24-2.984 4.171 4.171 0 00-1.21-2.924zm6.216-4.885l1.44 1.43L19.811 7.5l-1.44-1.43-1.917 1.903z" fill="inherit" /></svg>** dans la barre latérale gauche de l’éditeur de code.
        2. Sélectionnez **Add Secret**.
        3. Saisissez `SERVICE_URL` dans le champ **Name**.
        4. Saisissez l’URL du service externe dans le champ **Value**.
        5. Sélectionnez **Create**.

        <Frame>![Modules d’action - Secret ajouté](/docs/images/customize/actions/modules/actions-modules-secret.png)</Frame>

        Auth0 ajoute le Secret à la liste des Secrets du module d’action.
      </Tab>

      <Tab title="Management API">
        Ensuite, enregistrez l’URL du service externe comme Secret. Appelez [Update an Actions Module](/docs/fr-ca/api/management/v2/actions/patch-action-module) avec la permission `update:actions` :

        ```shell
        curl -L -X PATCH 'https://{yourDomain}/api/v2/actions/modules/{moduleId}' \
          -H 'Content-Type: application/json' \
          -H 'Authorization: Bearer {yourMgmtApiAccessToken}' \
          -d '{
            "secrets": [
              { "name": "SERVICE_URL", "value": "https://example.com/logs" }
            ]
          }'
        ```

        Chaque appel `PATCH` remplace l’ensemble du tableau `secrets` dans le brouillon du module. Incluez donc tous les Secrets dont le module a besoin, et non seulement celui que vous ajoutez.
      </Tab>

      <Tab title="Auth0 CLI">
        Ensuite, enregistrez l’URL du service externe comme Secret. Appelez [Update an Actions Module](/docs/fr-ca/api/management/v2/actions/patch-action-module) avec `auth0 api` :

        ```shell
        auth0 api patch actions/modules/{moduleId} --data '{
          "secrets": [
            { "name": "SERVICE_URL", "value": "https://example.com/logs" }
          ]
        }'
        ```

        Chaque appel remplace l’ensemble du tableau `secrets` dans le brouillon du module; incluez donc tous les Secrets dont le module a besoin, et non seulement celui que vous ajoutez.
      </Tab>

      <Tab title="Terraform">
        Ensuite, enregistrez l’URL du service externe comme Secret à l’aide d’un bloc `secrets` :

        ```terraform title="action-modules/logger.tf"
        resource "auth0_action_module" "logger" {
          name = "logger"
          code = file("${path.module}/action-modules/logger/code.js")

          secrets {
            name  = "SERVICE_URL"
            value = "https://example.com/logs"
          }
        }
        ```

        <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
          Nous ne prenons pas en charge la gestion partielle des `secrets`. Chaque `terraform apply` envoie la liste complète des secrets définis sur la ressource.
        </Callout>
      </Tab>

      <Tab title="Auth0 Déployer CLI">
        Ensuite, enregistrez l’URL du service externe comme Secret.

        <Tabs>
          <Tab title="YAML">
            Ajoutez un tableau `secrets` à l’entrée du module dans `tenant.yaml` :

            ```yaml highlight={3-5} title="tenant.yaml"
            actionModules:
              - name: logger
                secrets:
                  - name: SERVICE_URL
                    value: ##SERVICE_URL##
                code: ./action-modules/logger/code.js
            ```
          </Tab>

          <Tab title="Directory (JSON)">
            Ajoutez un tableau `secrets` à `action-modules/logger.json` :

            ```json highlight={3-5} title="action-modules/logger.json"
            {
              "name": "logger",
              "secrets": [
                { "name": "SERVICE_URL", "value": "##SERVICE_URL##" }
              ],
              "code": "./action-modules/logger/code.js"
            }
            ```
          </Tab>
        </Tabs>

        Le paramètre fictif `##SERVICE_URL##` est résolu par [remplacement de mots-clés](https://github.com/auth0/auth0-deploy-cli/blob/master/docs/keyword-replacement.md) au moment du déploiement, de sorte que la valeur réelle ne se trouve jamais dans votre fichier de configuration.
      </Tab>
    </Tabs>

    **Étape supplémentaire :** Répétez les étapes pour enregistrer un `API_KEY` comme Secret que vous enverrez dans les en-têtes au service externe avec chaque requête.

    <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
      Une fois un Secret créé, Auth0 n’en révèle jamais la valeur. Auth0 chiffre tous les Secrets et les stocke de façon sécurisée.
    </Callout>

    <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
      Chaque **Secret de module d’action** est indépendant des autres **Modules d’action** et des **Secrets des Actions**.
    </Callout>

    <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
      Utilisez les **Secrets** dans le module d’action en saisissant `actions.secrets.[secret_key]`.
    </Callout>
  </Step>

  <Step title="Ajouter de la logique personnalisée">
    Maintenant, ajoutez le code suivant à votre module d’action.

    <Tabs>
      <Tab title="Dashboard">
        Ajoutez le code suivant à votre module d’action :

        ```javascript
        module.exports = {
          sendLog: async (code, message) => {
            try {
              await fetch(actions.secrets.SERVICE_URL, {
                method: 'POST',
                headers: {
                  'X-API-Key': actions.secrets.API_KEY,
                },
                body: JSON.stringify({
                  code,
                  message
                }),
              });

              console.log({
                code,
                message
              });
            } catch (err) {
              throw new Error('External service failure');
            }

            return;
          }
        };
        ```
      </Tab>

      <Tab title="Management API">
        Appelez [Update an Actions Module](/docs/fr-ca/api/management/v2/actions/patch-action-module) avec la requête suivante :

        ```shell
        curl -L -X PATCH 'https://{yourDomain}/api/v2/actions/modules/{moduleId}' \
          -H 'Content-Type: application/json' \
          -H 'Authorization: Bearer {yourMgmtApiAccessToken}' \
          -d @code-update.json
        ```

        Où `code-update.json` contient le `code` du module sous forme de chaîne échappée en JSON :

        ```json title="code-update.json"
        {
          "code": "module.exports = {\n  sendLog: async (code, message) => {\n    try {\n      await fetch(actions.secrets.SERVICE_URL, {\n        method: 'POST',\n        headers: {\n          'X-API-Key': actions.secrets.API_KEY,\n        },\n        body: JSON.stringify({ code, message }),\n      });\n\n      console.log({ code, message });\n    } catch (err) {\n      throw new Error('External service failure');\n    }\n\n    return;\n  }\n};"
        }
        ```
      </Tab>

      <Tab title="Auth0 CLI">
        Enregistrez le code du module dans `code-update.json` :

        ```json title="code-update.json"
        {
          "code": "module.exports = {\n  sendLog: async (code, message) => {\n    try {\n      await fetch(actions.secrets.SERVICE_URL, {\n        method: 'POST',\n        headers: {\n          'X-API-Key': actions.secrets.API_KEY,\n        },\n        body: JSON.stringify({ code, message }),\n      });\n\n      console.log({ code, message });\n    } catch (err) {\n      throw new Error('External service failure');\n    }\n\n    return;\n  }\n};"
        }
        ```

        Puis transmettez-le à [Update an Actions Module](/docs/fr-ca/api/management/v2/actions/patch-action-module) au moyen de `auth0 api` :

        ```shell
        cat code-update.json | auth0 api patch actions/modules/{moduleId}
        ```
      </Tab>

      <Tab title="Terraform">
        1. Mettez à jour le fichier de code du module situé à `action-modules/logger/code.js` :

        ```javascript title="action-modules/logger/code.js"
        module.exports = {
          sendLog: async (code, message) => {
            try {
              await fetch(actions.secrets.SERVICE_URL, {
                method: 'POST',
                headers: {
                  'X-API-Key': actions.secrets.API_KEY,
                },
                body: JSON.stringify({
                  code,
                  message
                }),
              });

              console.log({
                code,
                message
              });
            } catch (err) {
              throw new Error('External service failure');
            }

            return;
          }
        };
        ```

        2. L’attribut `code` de la ressource `auth0_action_module` référence déjà ce fichier; exécutez donc `terraform apply` pour appliquer la modification.
      </Tab>

      <Tab title="Auth0 Deploy CLI">
        Mettez à jour `action-modules/logger/code.js` avec la logique du module :

        ```javascript title="action-modules/logger/code.js"
        module.exports = {
          sendLog: async (code, message) => {
            try {
              await fetch(actions.secrets.SERVICE_URL, {
                method: 'POST',
                headers: {
                  'X-API-Key': actions.secrets.API_KEY,
                },
                body: JSON.stringify({
                  code,
                  message
                }),
              });

              console.log({
                code,
                message
              });
            } catch (err) {
              throw new Error('External service failure');
            }

            return;
          }
        };
        ```
      </Tab>
    </Tabs>

  <Step title="Enregistrer le brouillon">
    Vous pouvez enregistrer un brouillon de votre Action Module.

    <Tabs>
      <Tab title="Dashboard">
        1. Sélectionnez **Save Draft**.

        <Frame>![Actions Modules - Brouillon enregistré](/docs/images/customize/actions/modules/actions-modules-draft.png)</Frame>
      </Tab>

      <Tab title="Management API">
        Il n’existe pas d’appel &quot;save&quot; distinct. Chaque requête [Update an Actions Module](/docs/fr-ca/api/management/v2/actions/patch-action-module) effectuée aux étapes précédentes a déjà enregistré vos modifications dans le brouillon du module. Vous pouvez le confirmer avec [Get an Actions Module](/docs/fr-ca/api/management/v2/actions/get-action-module) :

        ```shell
        curl -L 'https://{yourDomain}/api/v2/actions/modules/{moduleId}' \
          -H 'Authorization: Bearer {yourMgmtApiAccessToken}'
        ```

        Le champ `all_changes_published` de la réponse est `false`, ce qui confirme que le brouillon contient des modifications non publiées.
      </Tab>

      <Tab title="Auth0 CLI">
        Il n’existe pas d’appel &quot;save&quot; distinct. Chaque requête `auth0 api patch actions/modules/{moduleId}` effectuée aux étapes précédentes a déjà enregistré vos modifications dans le brouillon du module. Vous pouvez le confirmer avec [Get an Actions Module](/docs/fr-ca/api/management/v2/actions/get-action-module) :

        ```shell
        auth0 api get actions/modules/{moduleId}
        ```

        Le champ `all_changes_published` de la réponse est `false`, ce qui confirme que le brouillon contient des modifications non publiées.
      </Tab>

      <Tab title="Terraform">
        Il n’existe pas d’étape &quot;save&quot; distincte. La commande `terraform apply` que vous avez exécutée aux étapes précédentes a déjà mis à jour le brouillon du module. Le brouillon n’a aucun effet sur les Actions qui utilisent déjà une version publiée du module.
      </Tab>

      <Tab title="Auth0 Deploy CLI">
        Définissez `all_changes_published` à `false` dans l’entrée du module.

        <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
          Il n’existe pas d’étape &quot;save&quot; distincte.
        </Callout>

        <Tabs>
          <Tab title="YAML">
            Mettez à jour `tenant.yaml` :

            ```yaml highlight={3} title="tenant.yaml"
            actionModules:
              - name: logger
                all_changes_published: false
                secrets:
                  - name: SERVICE_URL
                    value: ##SERVICE_URL##
                code: ./action-modules/logger/code.js
            ```

            Redéployez la configuration pour publier la modification :

            ```shell
            a0deploy import -c=config.json --input_file=tenant.yaml
            ```
          </Tab>

          <Tab title="Directory (JSON)">
            Mettez à jour `action-modules/logger.json` :

            ```json highlight={2} title="action-modules/logger.json"
            {
              "all_changes_published": false,
              "name": "logger",
              "secrets": [
                { "name": "SERVICE_URL", "value": "##SERVICE_URL##" }
              ],
              "code": "./action-modules/logger/code.js"
            }
            ```

            Redéployez la configuration pour publier la modification :

            ```shell
            a0deploy import -c=config.json --input_file=local.
            ```
          </Tab>
        </Tabs>
      </Tab>
    </Tabs>

    Cette opération enregistre votre Action Module sans publier de nouvelle version; elle n’aura donc aucun effet sur les Actions qui l’utilisent.
  </Step>

  <Step title="Publier le module Action">
    Une fois que vous êtes satisfait du code de l’Action Module, il est temps de le **publier**.

    <Tabs>
      <Tab title="Dashboard">
        1. Sélectionnez **Publier**.

        <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
          La publication d’un Action Module en crée un instantané à ce moment précis et l’enregistre comme une **version d’Action Module**.
        </Callout>

        2. Sélectionnez **Afficher l’historique des versions**.

        <Frame>![Actions Modules - Historique des versions](/docs/images/customize/actions/modules/actions-modules-published-version.png)</Frame>

        Auth0 affiche la liste des versions d’Action Module, y compris le brouillon.
      </Tab>

      <Tab title="Management API">
        Appelez [Create an Actions Module Version](/docs/fr-ca/api/management/v2/actions/post-action-module-version), qui crée un instantané du brouillon actuel et le publie :

        ```shell
        curl -L -X POST 'https://{yourDomain}/api/v2/actions/modules/{moduleId}/versions' \
          -H 'Authorization: Bearer {yourMgmtApiAccessToken}'
        ```

        Auth0 retourne la nouvelle **version d’Action Module**, y compris son `id` et son `version_number`. Vous référencerez cet `id` comme `module_version_id` lorsque vous ajouterez le module à une Action.
      </Tab>

      <Tab title="Auth0 CLI">
        Appelez [Create an Actions Module Version](/docs/fr-ca/api/management/v2/actions/post-action-module-version) avec `auth0 api`, qui crée un instantané du brouillon actuel et le publie :

        ```shell
        auth0 api post actions/modules/{moduleId}/versions
        ```

        Auth0 retourne la nouvelle **version d’Action Module**, y compris son `id` et son `version_number`. Vous référencerez cet `id` comme `module_version_id` lorsque vous ajouterez le module à une Action.
      </Tab>

      <Tab title="Terraform">
        Définissez `publish` à `true` sur la ressource, puis exécutez `terraform apply` :

        ```terraform highlight={4} title="action-modules/logger.tf"
        resource "auth0_action_module" "logger" {
          name    = "logger"
          code    = file("${path.module}/action-modules/logger/code.js")
          publish = true

          secrets {
            name  = "SERVICE_URL"
            value = "https://example.com/logs"
          }
        }
        ```

        La publication crée une nouvelle **version d’Action Module** à partir du brouillon actuel. Terraform expose l’ID de la version publiée dans l’attribut calculé `version_id`, que vous référencez depuis les ressources `auth0_action` sous le nom `module_version_id`.
      </Tab>

      <Tab title="Auth0 Deploy CLI">
        Définissez `all_changes_published` à `true` dans l’entrée du module.

        <Tabs>
          <Tab title="YAML">
            Mettez à jour `tenant.yaml` :

            ```yaml highlight={3} title="tenant.yaml"
            actionModules:
              - name: logger
                all_changes_published: true
                secrets:
                  - name: SERVICE_URL
                    value: ##SERVICE_URL##
                code: ./action-modules/logger/code.js
            ```

            Redéployez la configuration pour publier le changement :

            ```shell
            a0deploy import -c=config.json --input_file=tenant.yaml
            ```
          </Tab>

          <Tab title="Directory (JSON)">
            Mettez à jour `action-modules/logger.json` :

            ```json highlight={2} title="action-modules/logger.json"
            {
              "all_changes_published": true,
              "name": "logger",
              "secrets": [
                { "name": "SERVICE_URL", "value": "##SERVICE_URL##" }
              ],
              "code": "./action-modules/logger/code.js"
            }
            ```

            Redéployez la configuration pour publier le changement :

            ```shell
            a0deploy import -c=config.json --input_file=local.
            ```
          </Tab>
        </Tabs>

        Cette opération publie une nouvelle **version d’Action Module** à partir du brouillon actuel, après l’application de vos changements.
      </Tab>
    </Tabs>

    Vous pouvez maintenant utiliser l’Action Module dans une Action.

    <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
      Chaque **Action** doit faire explicitement référence à la **version d’Action Module**, ce qui empêche les mises à niveau automatiques susceptibles d’introduire des erreurs inattendues.
    </Callout>
  </Step>

  <Step title="Ajouter l’Action Module à une Action">
    Ensuite, ajoutez le module d’action dans une action.

    <Tabs>
      <Tab title="Dashboard">
        1. Accédez à [Auth0 Dashboard &gt; Actions &gt; Library](https://manage.auth0.com/#/actions/library), puis sélectionnez une **Action** spécifique.
        2.       <Tab title="Management API">
        Appelez [Update an Action](/docs/fr-ca/api/management/v2/actions/patch-action) avec les valeurs `module_id` et `module_version_id` du module obtenues à l’étape précédente :

        ```shell
        curl -L -X PATCH 'https://{yourDomain}/api/v2/actions/actions/{actionId}' \
          -H 'Content-Type: application/json' \
          -H 'Authorization: Bearer {yourMgmtApiAccessToken}' \
          -d '{
            "modules": [
              {
                "module_id": "{moduleId}",
                "module_version_id": "{moduleVersionId}"
              }
            ]
          }'
        ```
      </Tab>

      <Tab title="Auth0 CLI">
        <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
          [`auth0 actions update`](https://auth0.github.io/auth0-cli/auth0_actions_update.html) n’a aucun indicateur pour les Action Modules; appelez donc directement [Update an Action](/docs/fr-ca/api/management/v2/actions/patch-action) avec `auth0 api`, en utilisant les `module_id` et `module_version_id` du module obtenus à l’étape précédente :
        </Callout>

        ```shell
        auth0 api patch actions/actions/{actionId} --data '{
          "modules": [
            {
              "module_id": "{moduleId}",
              "module_version_id": "{moduleVersionId}"
            }
          ]
        }'
        ```

      <Tab title="Terraform">
        Ajoutez un bloc `modules` à la ressource `auth0_action`, en y référençant le module et sa version publiée. Laissez l’attribut `code` pointer vers le fichier de code propre à l’Action :

        ```terraform highlight={3,5-8} title="actions/my-action.tf"
        resource "auth0_action" "my_action" {
          name = "my-action"
          code = file("${path.module}/actions/my-action/code.js")

          modules {
            module_id         = auth0_action_module.logger.id
            module_version_id = auth0_action_module.logger.version_id
          }

          supported_triggers {
            id      = "post-login"
            version = "v3"
          }
        }
        ```
      </Tab>

        Ajoutez un tableau `modules` à la configuration de l’Action, en référençant le module par son nom et son numéro de version.

        <Tabs>
          <Tab title="YAML">
            Ajoutez le tableau `modules` à l’entrée de l’Action dans `tenant.yaml` :

            ```yaml highlight={7-9} title="tenant.yaml"
            actions:
              - name: my-action

                  - id: post-login
            ```

  <Step title="Utilisez le module d’action dans l’Action">
    Maintenant, utilisons l’Action Module dans l’Action.

    <Tabs>
      <Tab title="Dashboard">
        1. Ajoutez l’instruction **require**.

        ```javascript
        const logger = require('actions:logger');
        ```

        <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
          L’instruction **require** fait référence à l’Action Module au format **actions:[module-name]**.
        </Callout>

        2. Ajoutez l’appel à `logger.sendLog` dans la **fonction Action**, à l’endroit où vous souhaitez envoyer des logs.

        ```javascript
        await logger.sendLog('logger_success', 'Your Action was able to use the Logger Action Module');
        ```

        3. Sélectionnez **Deploy** pour déployer l’Action.

        <Frame>![Actions - Use Action Module](/docs/images/customize/actions/modules/actions-modules-use-module.png)</Frame>
      </Tab>

      <Tab title="Management API">
        1. Appelez [Update an Action](/docs/fr-ca/api/management/v2/actions/patch-action) pour ajouter l’instruction `require` et l’appel à `logger.sendLog` au `code` de l’Action :

        ```shell
        curl -L -X PATCH 'https://{yourDomain}/api/v2/actions/actions/{actionId}' \
          -H 'Content-Type: application/json' \
          -H 'Authorization: Bearer {yourMgmtApiAccessToken}' \
          -d @code-update.json
        ```

        Où `code-update.json` contient :

        ```json title="code-update.json"
        {
          "code": "const logger = require('actions:logger');\n\nexports.onExecutePostLogin = async (event, api) => {\n  await logger.sendLog('logger_success', 'Your Action was able to use the Logger Action Module');\n};"
        }
        ```

        2. Appelez [Deploy an Action](/docs/fr-ca/api/management/v2/actions/post-deploy-action) :

        ```shell
        curl -L -X POST 'https://{yourDomain}/api/v2/actions/actions/{actionId}/deploy' \
          -H 'Authorization: Bearer {yourMgmtApiAccessToken}'
        ```
      </Tab>

      <Tab title="Auth0 CLI">
        1. Mettez à jour le fichier de code de l’Action situé à `actions/my-action/code.js` avec l’instruction `require` et l’appel à `logger.sendLog` :

        ```javascript title="actions/my-action/code.js"
        const logger = require('actions:logger');

        exports.onExecutePostLogin = async (event, api) => {
          await logger.sendLog('logger_success', 'Your Action was able to use the Logger Action Module');
        };
        ```

        2. Mettez à jour l’Action avec [`auth0 actions update`](https://auth0.github.io/auth0-cli/auth0_actions_update.html) et déployez-la avec [`auth0 actions deploy`](https://auth0.github.io/auth0-cli/auth0_actions_deploy.html) :

        ```shell
        auth0 actions update {actionId} --code "$(cat actions/my-action/code.js)"
        auth0 actions deploy {actionId}
        ```
      </Tab>

      <Tab title="Terraform">
        1. Mettez à jour le fichier de code de l’Action situé à `actions/my-action/code.js` avec l’instruction `require` et l’appel à `logger.sendLog` :

        ```javascript title="actions/my-action/code.js"
        const logger = require('actions:logger');

        exports.onExecutePostLogin = async (event, api) => {
          await logger.sendLog('logger_success', 'Your Action was able to use the Logger Action Module');
        };
        ```

        2. Définissez `deploy` à `true` sur la ressource `auth0_action`, puis exécutez `terraform apply` :

        ```terraform highlight={3} title="actions/my-action.tf"
        resource "auth0_action" "my_action" {
          name    = "my-action"
          deploy  = true
          code    = file("${path.module}/actions/my-action/code.js")

          modules {
            module_id         = auth0_action_module.logger.id
            module_version_id = auth0_action_module.logger.version_id
          }

          supported_triggers {
            id      = "post-login"
            version = "v3"
          }
        }
        ```

        Définir `deploy = true` crée immédiatement une nouvelle version déployée de l’Action.
      </Tab>

      <Tab title="Auth0 Deploy CLI">
        1. Ajoutez l’instruction `require` et l’appel à `logger.sendLog` dans `actions/my-action/code.js` :

        ```javascript title="actions/my-action/code.js"
        const logger = require('actions:logger');

        exports.onExecutePostLogin = async (event, api) => {
          await logger.sendLog('logger_success', 'Your Action was able to use the Logger Action Module');
        };
        ```

        2. Redéployez la configuration :

        ```shell
        a0deploy import -c=config.json --input_file=local.
        ```
      </Tab>
    </Tabs>

    <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
      N’oubliez pas d’associer l’Action à un Trigger.
    </Callout>
  </Step>
</Steps>

      Auth0 ajoute la dépendance à la liste des dépendances du Action Module.
    </Tab>

    <Tab title="Management API">
      Appelez [Update an Actions Module](/docs/fr-ca/api/management/v2/actions/patch-action-module) avec un tableau `dependencies` :

      ```shell
      curl -L -X PATCH 'https://{yourDomain}/api/v2/actions/modules/{moduleId}' \
        -H 'Content-Type: application/json' \
        -H 'Authorization: Bearer {yourMgmtApiAccessToken}' \
        -d '{
          "dependencies": [
            { "name": "lodash", "version": "4.17.21" }
          ]
        }'
      ```

      Comme pour les `secrets`, chaque appel `PATCH` remplace l’intégralité du tableau `dependencies`; incluez donc toutes les dépendances dont le module a besoin.
    </Tab>

    <Tab title="Auth0 CLI">
      Appelez [Update an Actions Module](/docs/fr-ca/api/management/v2/actions/patch-action-module) avec `auth0 api`, en utilisant un tableau `dependencies` :

      ```shell
      auth0 api patch actions/modules/{moduleId} --data '{
        "dependencies": [
          { "name": "lodash", "version": "4.17.21" }
        ]
      }'
      ```

      Comme pour `secrets`, chaque appel remplace l’ensemble du tableau `dependencies` : incluez donc toutes les dépendances dont le module a besoin.
    </Tab>

    <Tab title="Terraform">
      Ajoutez un bloc `dependencies` à la ressource `auth0_action_module`, puis exécutez `terraform apply` :

      ```terraform highlight={4-7} title="action-modules/logger.tf"
      resource "auth0_action_module" "logger" {
        name = "logger"
        code = file("${path.module}/action-modules/logger/code.js")

        dependencies {
          name    = "lodash"
          version = "4.17.21"
        }
      }
      ```
    </Tab>

    <Tab title="CLI Auth0 Deploy">
      Ajoutez un tableau `dependencies` à la configuration du module.

      <Tabs>
        <Tab title="YAML">
          Ajoutez le tableau `dependencies` à l’entrée du module dans `tenant.yaml` :

          ```yaml highlight={3-5} title="tenant.yaml"
          actionModules:
            - name: logger
              dependencies:
                - name: lodash
                  version: 4.17.21
              code: ./action-modules/logger/code.js
          ```
        </Tab>

        <Tab title="Directory (JSON)">
          Ajoutez le tableau `dependencies` à `action-modules/logger.json` :

          ```json highlight={2-4} title="action-modules/logger.json"
          {
            "dependencies": [
              { "name": "lodash", "version": "4.17.21" }
            ],
            "name": "logger",
            "code": "./action-modules/logger/code.js"
          }
          ```
        </Tab>
      </Tabs>
    </Tab>
  </Tabs>

  <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
    Utilisez les **dépendances** répertoriées dans le Action Module en les important avec `require('[package-name]')`.
  </Callout>

  <Callout icon="file-lines" color="#0EA5E9" iconType="regular">

    Vous pouvez fournir une version précise au lieu de latest.
  </Callout>
