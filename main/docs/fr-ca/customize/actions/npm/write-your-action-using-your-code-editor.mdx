Utilisez le paquet NPM [`@auth0/actions`](https://www.npmjs.com/package/@auth0/actions) pour écrire et soumettre vos Actions à des tests unitaires dans votre propre éditeur de code ou IDE, avec toutes les fonctions d&#39;IntelliSense, de vérification des types et de détection des erreurs.

<Steps titleSize="h3">
  <Step title="Installer le paquet">
    Utilisez l’un des gestionnaires de paquets suivants pour installer le paquet :

    <Tabs>
      <Tab title="NPM">
        <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
          Utilisez `--save-dev` lors de l’installation du paquet pour indiquer qu’il s’agit d’une dépendance de développement venant compléter vos outils de développement.
        </Callout>

        <InstallNPM />
      </Tab>

      <Tab title="Yarn">

        <InstallYarn />
      </Tab>

      <Tab title="Pnpm">
        <Callout icon="file-lines" color="#0EA5E9" iconType="regular">

        <InstallPNPM />
      </Tab>
    </Tabs>
  </Step>

  <Step title="Importer les définitions de types">
    Utilisez l’une des options suivantes pour importer les définitions TypeScript dans vos Actions, selon votre technologie :

    <Tabs>
      <Tab title="JSDocs @import">
        Choisissez cette option si vous voulez profiter d’IntelliSense sans modifier la structure de votre code JavaScript existant :

        <JSDocsImport />
      </Tab>

      <Tab title="JSDocs @param">
        Choisissez cette option pour assurer la sûreté de typage dans les fichiers JavaScript au moyen d’instructions d’importation placées dans les commentaires JSDoc :

        <JSDocsParam />
      </Tab>

      <Tab title="TS types import">
        Choisissez cette option si vous développez avec TypeScript, pour une vérification de types complète et une syntaxe moderne :

        <TSTypesImport />
      </Tab>
    </Tabs>

    <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
      L’instruction d’importation doit reposer sur le **nom du trigger** et le **numéro de version**, en tenant compte de la [structure de la bibliothèque](#library-structure).

      **Suivez ce modèle** : `@auth0/actions/[trigger_name]/[trigger_version]`

      **Par exemple** : `@auth0/actions/post-login/v3`
    </Callout>

    <Accordion title="Structure de la bibliothèque">
      <Structure />
    </Accordion>
  </Step>

  <Step title="Configurer votre projet">
    Les exemples de configuration suivants sont volontairement présentés en JavaScript et en TypeScript, afin d’offrir une comparaison directe, côte à côte.

        <TSConfig />

    </Tabs>
  </Step>

  <Step title="Rédiger le code de votre Action">
    L’exemple d’Action suivant s’exécuterait pendant le flux Post-Login. Il vérifie si des rôles sont attribués à l’utilisateur et appelle `api.access.deny()` si aucun rôle n’est trouvé. Si des rôles sont présents, il définit ensuite la demande personnalisée dans le jeton d’ID.

    L’instruction d’importation rend les types externes accessibles à votre code. L’éditeur connaît ainsi la structure des objets `event` et `api`.

    <Tabs>
      <Tab title="JavaScript">
        <JSExample />
      </Tab>

      <Tab title="TypeScript">
        <TSExample />

        <Warning>
          Si vous utilisez TypeScript, vous devez compiler votre code en JavaScript avant de le déployer dans Auth0. L’environnement d’exécution d’Auth0 Actions n’exécute que du JavaScript. Utilisez le compilateur TypeScript (`tsc`) pour transpiler vos fichiers `.ts` en fichiers `.js` avant de pouvoir les déployer. Vous devez aussi inclure des commentaires JSDoc pour activer IntelliSense dans le Dashboard.
        </Warning>
      </Tab>
