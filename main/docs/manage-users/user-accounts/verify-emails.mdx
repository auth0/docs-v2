When a user supplies an email address, you can verify that the user has access to that email address before your application uses it. For example, you may want to verify user email addresses if your application sends emails to users, uses email addresses as a search index or to recommend account linking, or lets users create accounts connected to an email address.

<Warning>
We do not recommend using an email address as a way to validate that a user is who they say they are. Email verification can lower the risk of accounts being compromised, but your application may also need other security measures.
</Warning>

Auth0 tracks the verification status of a user's email address with the `email_verified` user profile attribute. There are several ways to set and unset this attribute depending on your connection type and workflow:

* If you are using a federated identity provider (IdP), as with social connections and enterprise connections, the `email_verified` attribute is set to what the IdP returns in the user profile.

* If you are using an Auth0 database connection, our built-in email verification can automatically email a verification link or one-time password when a user signs up. You can also use the Management API to generate or email a verification link as part of your own workflows.

* You can use the Management API to set the `email_verified` attribute of a user profile directly.

## Email verification for federated IdPs

If you are using a federated identity provider (IdP), as with social connections and enterprise connections, the `email_verified` attribute is set to what the IdP returns in the user profile.

We provide an additional [email verification property for Azure AD and ADFS enterprise connections](/docs/authenticate/identity-providers/enterprise-identity-providers/azuread-adfs-email-verification) because of how those IdPs handle email verification.

## Email verification for database connections

Auth0 database connections support two email verification methods:

* **Verification Links** (default): We email a verification link to the given email address. When the user follows the link, the email address is verified.

    Verification links only require the user to follow the link, but can cause accidental verification if the link is followed unintentionally (for example, by an email scanner or even by the user themselves).

* **One-Time Passwords (OTPs)**: We email a single use code to the given email address. When the user enters the code, the email address is verified.

    OTPs require the user to transpose the code from the email, so accidental verification is less likely, but it requires slightly more manual work from the user.

### Configure verification method and sign-up verification emails

To configure your database connection's verification method and automatic sign-up verification emails:

1. Navigate to [Auth0 Dashboard > Authentication > Database Connections](https://manage.auth0.com/dashboard/us/hazels-example-tenant/connections/database) and select your database connection.

2. From the **Attributes** tab, next to **Email**, select **Configure** to open the **Email Configuration** window.

3. Under **Verification Method**, choose either **Email Verification Link** or **One-Time Password (OTP)**.

4. Check or uncheck **Verify email on sign up**.

5. Select **Save**.

## Email verification links

A common way to verify emails with Auth0 is to send an email verification link to the user. When the user clicks the link, the user's `email_verified` flag is set to `true`.

By default, Auth0 emails verification links to users when they sign up.

You can also customize when Auth0 sends verification emails (for example, if you want to delay verification until the user performs an action requiring a verified email).

To control when users receive a verification email, you can:

* Use the Management API to [email a verification link](/docs/api/management/v2/jobs/post-verification-email) to the user based on the verification email template.

* Use the Management API to [generate an email verification URL](/docs/api/management/v2/tickets/post-email-verification) and email the link to the user yourself.

## One-time passwords

[One-time passwords (OTPs)](/docs/authenticate/passwordless/authentication-methods/email-otp) can be emailed to each new user at the time of account creation to ensure every user has an verified email. Because email verification links can lead to accidental verification by email scanners or the users themselves, OTPs ensures each user actively verifies an existing email address. To use OTPs, your tenant must have [Universal Login](/docs/authenticate/login/auth0-universal-login), [Flexible Identifiers](/docs/authenticate/database-connections/flexible-identifiers-and-attributes), and [Identifer-First login](/docs/authenticate/login/auth0-universal-login/identifier-first) enabled.

<Callout icon="file-lines" color="#0EA5E9" iconType="regular">
OTP tokens for phone and email identifier verification have a lifetime of 900 seconds.
</Callout>

To set up OTPs, go to [**Authentication > Database**](https://manage.auth0.com/#/authentication) and select the connection to change, then pick **Attributes**, locate **Email,** choose the menu button,and enable **One-Time Password (OTP)**.

## Custom or bulk verification with the Management API

<Warning>
This works for social and database connections but does not work for enterprise connections. The `email_verified` field may be overwritten by the social identity provider if the data comes from them.
</Warning>

In some cases, you may want to verify email through other means. For example, you have a list of users to verify in bulk or you have some other means for verifying a user's email through a custom workflow you've built yourself.

In these cases you can use the [PATCH `/api/v2/users` endpoint](https://auth0.com/docs/api/management/v2/#!/Users/patch_users_by_id) to set `email_verified` to `true`.

## Special verification support

For Azure AD and ADFS enterprise connections, Auth0 supports some custom email verification workflows. This can help you ensure users coming from other systems have verified emails in an accurate and secure way. To learn more, read [Email Verification for Azure AD and ADFS](/docs/authenticate/identity-providers/enterprise-identity-providers/azuread-adfs-email-verification).
