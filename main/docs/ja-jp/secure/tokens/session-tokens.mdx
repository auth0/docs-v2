認証済みユーザーが存在しない[匿名ユーザー](/docs/ja-jp/manage-users/sessions/anonymous-sessions)フローでは、Auth0 は匿名でセッションを確立するための仕組みを提供します。

Auth0 は、[`/anonymous/token`](/docs/ja-jp/manage-users/sessions/anonymous-sessions#gather-anonymous-sessions-data)リクエストに応じて、セッショントークンと[アクセストークン](/docs/ja-jp/secure/tokens/access-tokens)を発行します。詳細については、[匿名セッションの設定](/docs/ja-jp/manage-users/sessions/anonymous-sessions/configure-anonymous-sessions)を参照してください。

<Callout icon="file-lines" color="#0EA5E9" iconType="regular">
  * セッショントークンには、匿名ユーザーのアイデンティティとセッション情報の属性が含まれます。
  * アクセストークンは通常、リソースサーバー (API) がクレームを読み取り、処理できる[JSON Web トークン (JWT) ](/docs/ja-jp/secure/tokens/json-web-tokens)です。一方、セッショントークンは不透明であり、Auth0 のみが読み取ることを想定しています。
</Callout>

通常、ユーザーが初めてリソースにアクセスする場合や、以前に付与されたアクセストークンの有効期限が切れた後には、新しいアクセストークンが必要になります。

セッショントークンは、必要に応じて新しいアクセストークンを取得するためにアプリケーションで使用できる認証情報です。[`anonymous_session_lifetime`](/docs/ja-jp/manage-users/sessions/anonymous-sessions/configure-anonymous-sessions#configure-anonymous-sessions-in-your-auth0-tenant)の有効期限が切れるまで、新しいアクセストークンを引き続きリクエストできます。

<div id="session-token-benefits">
  ## セッショントークンの利点
</div>

* セッショントークンは、セッションを作成したデバイスに紐付けられません。別のデバイスに移行して使用できます。

* セッショントークンは認可リクエストに含めることができ、ログイントランザクションを補完するため、セッショントークン内の情報を[Actions](/docs/ja-jp/customize/actions/actions-overview)で利用できます。
