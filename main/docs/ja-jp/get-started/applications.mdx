---
title: Auth0のアプリケーションの種類
description: Auth0におけるアプリケーションの種類と、アプリケーションの登録および設定の基本について説明します。
---

Auth0では、次の特性に基づいてアプリケーションを分類します。

* **アプリケーションの種類**：従来型Webアプリケーション、シングルページWebアプリケーション、ネイティブアプリケーション、またはマシンツーマシンアプリケーションのいずれかです。

  * [従来型Webアプリケーション](/docs/ja-jp/get-started/auth0-overview/create-applications/regular-web-apps)は、アプリケーションロジックの大部分をサーバー上で実行する従来型のWebアプリです (Express.js や ASP.NET など) 。

  * [シングルページWebアプリケーション (SPA) ](/docs/ja-jp/get-started/auth0-overview/create-applications/single-page-web-apps)は、ユーザーインターフェースロジックの大部分をWebブラウザーで実行し、主にAPIを使用してWebサーバーと通信するJavaScriptアプリです (AngularJS + Node.js や React など) 。

  * [ネイティブアプリケーション](/docs/ja-jp/get-started/auth0-overview/create-applications/native-apps)は、デバイス上でネイティブに動作するモバイルまたはデスクトップアプリケーションです (iOS や Android など) 。

  * [マシンツーマシン (M2M) アプリケーション](/docs/ja-jp/get-started/auth0-overview/create-applications/machine-to-machine-apps)は、コマンドラインツール、デーモン、IoTデバイス、バックエンドで実行されるサービスなど、ユーザー操作を伴わないアプリケーションです。通常、APIへのアクセスが必要なサービスがある場合にこのオプションを使用します。

* **資格情報のセキュリティ**は、アプリがsecretsを保存できるかどうかを示します。アプリは[パブリックまたは機密](/docs/ja-jp/get-started/applications/confidential-and-public-applications)に分類されます。

  * パブリックアプリケーションは資格情報を安全に保存できません。

  * 機密アプリケーションは資格情報を安全に保存できます。

* **所有権**は、アプリの信頼関係 (アプリケーションを所有・運用するのは誰か) を示します。[ファーストパーティまたはサードパーティ](/docs/ja-jp/get-started/applications/first-party-and-third-party-applications)のいずれかに分類されます。

  * ファーストパーティアプリは、Auth0ドメインを所有するorganizationまたは個人によって管理されます。

  * サードパーティアプリは、外部の関係者やパートナーがAPIの背後にある保護されたリソースに安全にアクセスできるようにします。

<div id="manage-application-settings">
  ## アプリケーション設定の管理
</div>

アプリケーションは、[Auth0 Dashboard &gt; アプリケーション &gt; アプリケーション](https://manage.auth0.com/#/applications/\{yourClientId}/settings) で登録します。Auth0 Dashboard でアプリケーションを設定するだけでなく、[OpenID Connect (OIDC) Dynamic Client Registration 1.0](https://openid.net/specs/openid-connect-registration-1_0.html) 仕様で説明されているように、プログラムから設定することもできます。

アプリごとに異なる方法でユーザーがログインできるような、より複雑な構成にすることもできます。詳しくは、[Multi-Tenant Application Best Practices](/docs/ja-jp/get-started/auth0-overview/create-tenants/multi-tenant-apps-best-practices) と [Create Multiple Tenants](/docs/ja-jp/get-started/auth0-overview/create-tenants/create-multiple-tenants) を参照してください。

デフォルトでは、Auth0 は新しいアプリケーションを作成するときに、テナントに関連付けられているすべての接続を有効にします。これを変更するには、Auth0 Dashboard の **アプリケーション設定** で [アプリケーションの接続を更新](/docs/ja-jp/get-started/applications/update-application-connections) します。

<div id="monitor-applications">
  ## アプリケーションを監視する
</div>

[アプリケーション](/docs/ja-jp/deploy-monitor/monitor/monitor-applications)を監視し、独自のテストを使用してエンドツーエンドテストを実行できます。Auth0 では、Auth0 Dashboard 管理者の操作、ユーザー認証の成功と失敗、パスワード変更リクエストなどを含む[ログデータ](/docs/ja-jp/deploy-monitor/logs)が保存されます。[Auth0 Marketplace](https://marketplace.auth0.com/features/log-streaming) のログストリーミングを使用すると、ログデータをエクスポートし、Sumo Logic、Splunk、Mixpanel などのツールでログデータを分析・保存できます。

<div id="manage-client-secrets">
  ## クライアントシークレットを管理する
</div>

<Tooltip tip="Authorization Server: ユーザーのアクセス範囲の境界を定義する役割を担う中央集約型サーバー。たとえば、認可サーバーは、ユーザーが利用できるデータ、タスク、機能を制御できます。" cta="用語集を見る" href="/docs/ja-jp/glossary?term=client+secret">クライアントシークレット</Tooltip>は、アプリケーションと<Tooltip tip="Client Secret: クライアント（アプリケーション）が認可サーバーに対して認証を行うために使用するシークレット。クライアントと認可サーバーだけが知っているべきであり、推測されないよう十分にランダムでなければなりません。" cta="用語集を見る" href="/docs/ja-jp/glossary?term=authorization+server">認可サーバー</Tooltip>だけが知っているシークレットです。これにより、認可されたリクエスト送信元にのみ[トークン](/docs/ja-jp/secure/tokens)を付与し、リソースを保護します。

クライアントシークレットは厳重に保護し、モバイルアプリや**ブラウザベース**のアプリには**決して**含めないでください。クライアントシークレットが万一漏えいした場合は、[新しいものにローテーション](/docs/ja-jp/get-started/applications/rotate-client-secret)し、新しいクライアントシークレットで認可済みのすべてのアプリケーションを更新してください。

<div id="grant-types">
  ## グラントタイプ
</div>

Auth0 では、さまざまな認証および認可のグラントタイプやフローが提供されており、Auth0 に登録したアプリケーションの `grant_types` プロパティに基づいて、適切なグラントタイプを指定できます。詳しくは、[アプリケーションのグラントタイプ](/docs/ja-jp/get-started/applications/application-grant-types) を参照してください。
