Get User スクリプトは、ユーザーの存在状況を確認する際に実行される関数を実装します。この関数には `getUser` という名前を付けることをお勧めします。

このスクリプトは、[Auth0 への自動移行](/docs/ja-jp/manage-users/user-migration/configure-automatic-migration-from-your-database)に必要です。また、移行が有効でない場合は、接続に設定された操作に応じて必要になることがあります。Auth0 では、ユーザープロファイルで返す `user_id` を永続的かつ一貫したものにすることを強く推奨します。特定のユーザーについては、Get User スクリプトは実行のたびに同じ `user_id` を返す必要があります。詳細については、[一貫した user&#95;id を返す](#return-a-consistent-user-id)を参照してください。

**Import Users to Auth0** が有効な場合、ユーザーがサインアップを試みると、外部ユーザーストアにそのユーザーがすでに存在するかどうかを確認するために Get User スクリプトが実行されます。

ユーザーが以下を試みる場合も、Get User スクリプトが実行されます。

* メールアドレスを変更する ([Change Email](/docs/ja-jp/authenticate/database-connections/custom-db/templates/change-email) スクリプト)
* ログインする ([Login](/docs/ja-jp/authenticate/database-connections/custom-db/templates/login) スクリプト)
* パスワードを変更する ([Change Password](/docs/ja-jp/authenticate/database-connections/custom-db/templates/change-password) スクリプト)

**Import Users to Auth0** が無効な場合も、ユーザーがサインアップを試みると、外部ユーザーストアにそのユーザーがすでに存在するかどうかを確認するために Get User スクリプトが実行されます。ユーザーがすでに外部ユーザーストアに存在する場合、Create スクリプトは実行されません。

ユーザーが以下を試みる場合も、Get User スクリプトが実行されます。

* サインアップする  ([Create](/docs/ja-jp/authenticate/database-connections/custom-db/templates/create) スクリプト)
* メールアドレスを変更する  ([Change Email](/docs/ja-jp/authenticate/database-connections/custom-db/templates/change-email) スクリプト)
* パスワードを変更またはリセットする  ([Change Password](/docs/ja-jp/authenticate/database-connections/custom-db/templates/change-password) スクリプト)

<div id="get-user-function">
  ## Get User 関数
</div>

`getUser` 関数は、次の処理を行う必要があります。

* ユーザーの識別子を外部データベースの API に送信する。
* ユーザーが見つかった場合は、そのユーザーのプロファイルデータを返す。
* ユーザーが存在するかどうかの判定時に問題が発生した場合は、エラーを返す。

<div id="definition">
  ### 定義
</div>

`getUser` 関数は2つのパラメータを受け取り、`callback` コールバック関数を返します。

```js lines
getUser(email, callback): function
```

| パラメータ      | 型        | 説明                                      |
| ---------- | -------- | --------------------------------------- |
| `email`    | String   | ユーザーのメールアドレス。                           |
| `callback` | Function | エラーまたはプロファイルデータをパイプラインを通じて渡すために使用されます |

これは、`getUser` 関数の実装方法を示した擬似Javascriptの例です。

```javascript lines expandable
function getUser(email, callback) {
  // 外部データベースAPIにユーザー識別子を送信する
  let options = {
    url: "https://example.com/api/search-users",
    body: {
      email: email
    }
  };

  send(options, (err, profileData) => {
    // ユーザーの検索中に問題が発生した場合、コールバックでエラーを返す
    if (err) {
      return callback(new Error("Could not determine if user exists or not."));
    } else {
      // ユーザーが見つからなかった場合はコールバックでnullを返し、見つかった場合はプロファイルデータを返す
      if (!profileData) {
        return callback(null);
      } else {
        let profile = {
          email: profileData.email,
          user_id: profileData.userId
        };

        return callback(null, profile);
      }
    }
  });
}
```

<div id="callback-function">
  ## コールバック関数
</div>

`callback` 関数は、ユーザープロファイルデータやエラーデータをパイプライン内で受け渡すために使用されます。

<div id="definition-2">
  ### 定義
</div>

`callback` 関数は最大2つのパラメータを受け取り、関数を返します。

```js lines
callback(error[,profile]): function
```

| パラメータ     | 型      | 必須 | 説明                    |
| --------- | ------ | -- | --------------------- |
| `error`   | オブジェクト | 必須 | エラーデータが含まれます。         |
| `profile` | オブジェクト | 任意 | ユーザーのプロファイルデータが含まれます。 |

<div id="return-the-user-profile-user-found">
  ### ユーザープロファイルを返す (ユーザーが見つかった場合)
</div>

<Warning>
  ユーザーについて Get User スクリプトが返すプロファイルデータは、Login スクリプトが返すプロファイルデータと一致している必要があります。
</Warning>

ユーザーが見つかった場合は、`error` パラメータに `null` を渡し、`profile` パラメータには[正規化された形式](/docs/ja-jp/manage-users/user-accounts/user-profiles/normalized-user-profile-schema)のユーザーのプロファイルデータを渡します。

```js lines
return callback(null, {
    username: "username",
    user_id: "my-custom-db|username@domain.com",
    email: "username@domain.com",
    email_verified: false,
    user_metadata: {
        language: "en"
    },
    app_metadata: {
        plan: "full"
    },
    mfa_factors: [
      {
        phone: {
          value: "+15551234567"
        }
      },
    ]
});
```

標準フィールドに加えて、`user_metadata`、`app_metadata`、`mfa_factors` フィールドを含めることもできます。

<div id="return-a-consistent-user_id">
  ### 常に同じ user_id を返す
</div>

Auth0 は、Get User スクリプトから返された `user_id` を使用して、テナント全体でユーザーを識別します。特定のユーザーについて、この値は**常に同じ**である必要があります。Get User スクリプトは、そのユーザーに対して実行されるたびに同じ `user_id` を返す必要があります。`user_id` は、実行ごとに変化する値ではなく、ソースレコードの安定した永続的なプロパティ (データベースの主キーなど) から導出してください。

<Callout icon="file-lines" color="#0EA5E9" iconType="regular">
  一貫性のない `user_id` を返すと、重複ユーザーや孤立したユーザーが作成され、識別子が安定していることを前提とするフローが機能しなくなる可能性があります。
</Callout>

`user_id` はソースレコードの安定したプロパティから導出し、同じユーザーが常に同じ値にマッピングされるようにしてください。

```js lines
return callback(null, {
    // `user.id` はデータベースの不変の主キーです
    user_id: "my-custom-db|" + user.id,
    email: user.email,
    email_verified: user.email_verified
});
```

呼び出すたびに新しい、またはランダムな `user_id` を生成しないでください。たとえば、毎回新たに生成した UUID を返す場合です。そうすると、同じユーザーに対してスクリプトが実行されるたびに異なる識別子が生成されます。

```js lines
const { v4: uuidv4 } = require("uuid");

return callback(null, {
    // アンチパターン: 実行のたびに新しい値が生成されるため、Auth0 では毎回新しいユーザーとして扱われます
    user_id: uuidv4(),
    email: user.email,
    email_verified: user.email_verified
});
```

<div id="return-no-user-profile-user-not-found">
  ### ユーザープロファイルを返さない (ユーザーが見つからない場合)
</div>

ユーザーが見つからない場合は、`error` パラメータには `null` を渡し、`profile` パラメータは省略します：

```js lines
return callback(null);
```

<div id="return-an-error">
  ### エラーを返す
</div>

エラーが発生した場合は、問題の内容がわかる関連情報とともに、エラーデータを `error` パラメータに渡します。

```js lines
return callback(new Error("My custom error message."));
```

詳しくは、[カスタムデータベースのトラブルシューティング](/docs/ja-jp/authenticate/database-connections/custom-db/error-handling)を参照してください。

      const query =
        'SELECT Memberships.UserId, Email, Users.UserName ' +
        'FROM Memberships INNER JOIN Users ' +
        'ON Users.UserId = Memberships.UserId ' +
        'WHERE Memberships.Email = @Username OR Users.UserName = @Username';
      const getMembershipQuery = new Request(query, function(err, rowCount) {
        if (err) return callback(err);
        if (rowCount < 1) return callback();
        callback(null, user);

      getMembershipQuery.addParameter('Username', TYPES.VarChar, email);

        user = {
          user_id: fields.UserId.value,
          nickname: fields.UserName.value,
          email: fields.Email.value
        };
      });
      connection.execSql(getMembershipQuery);
    });
  }

  function getByEmail(email, callback) {
