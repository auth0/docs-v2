## エンドポイント {#endpoint}

`POST /oidc/register`

名前と必要なコールバック URL を指定すると、Auth0 でクライアントを動的に登録できます。このリクエストにトークンは不要です。

## Body パラメータ {#body-parameters}

<ParamField body="client_name" type="string">
  作成する Dynamic Client の名前。
</ParamField>

<ParamField body="grant_types" type="array">
  クライアントが使用できるグラントタイプの一覧。指定しない場合、セキュリティ制御が強化された <a href="https://auth0.com/docs/get-started/applications/third-party-applications">サードパーティアプリ</a> には、デフォルトで `authorization_code` グラントタイプが適用されます。
</ParamField>

<ParamField body="redirect_uris" type="array" required>
  Authentication フローの完了時に Auth0 が有効な呼び出し先と見なす URL の配列。
</ParamField>

<ParamField body="token_endpoint_auth_method" type="string">
  トークンエンドポイントでの認証に使用する方式。
</ParamField>

## レスポンススキーマ {#response-schema}

<ResponseSchema>
  <ResponseField name="client_name" type="string">
    新たに登録されたクライアントの名前。
  </ResponseField>

  <ResponseField name="client_id" type="string">
    クライアントの一意の識別子。
  </ResponseField>

  <ResponseField name="client_secret" type="string">
    クライアントシークレット。
  </ResponseField>

  <ResponseField name="client_secret_expires_at" type="integer">
    クライアントシークレットの有効期限が切れる時刻。
  </ResponseField>
</ResponseSchema>

## レスポンスメッセージ {#response-messages}

| ステータス | 説明                 |
| ----- | ------------------ |
| 200   | クライアントの詳細を含む正常な応答。 |
