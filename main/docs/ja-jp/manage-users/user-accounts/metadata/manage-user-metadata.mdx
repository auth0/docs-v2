ユーザープロファイルの`user_metadata`と`app_metadata`には、ユースケースに応じてさまざまなメソッドでアクセスし、値を設定できます。

<Tabs>
  <Tab title="Management API">
    [Management APIのユーザー作成エンドポイント](/docs/ja-jp/api/management/v2/users/post-users) (`POST /users`) で新しいユーザーを作成する際は、ボディパラメーターの`user_metadata`と`app_metadata`を指定することで、そのユーザーのメタデータを設定できます。

    <Accordion title="例：メタデータ付きの新規ユーザーを作成">
      次のプロフィール情報でユーザーを作成するには：

      ```json
      {
          "email": "jane.doe@example.com",
          "user_metadata": {
              "hobby": "surfing"
          },
          "app_metadata": {
              "plan": "full"
          }
      }
      ```

      <Tooltip tip="Management API：顧客が管理タスクを実行できるようにする製品です。" cta="用語集を表示" href="/docs/ja-jp/glossary?term=Management+API">Management API</Tooltip>の[`/post_users`](https://auth0.com/docs/api/management/v2#!/Users/post_users)エンドポイントに対して次の`POST`呼び出しを行い、ユーザーを作成してプロパティ値を設定します：

      <Callout icon="file-lines" color="#0EA5E9" iconType="regular">Auth0 CLIをご利用ですか？まだの場合は、このコマンドを実行する前に[CLIセッションのセットアップと認証](/docs/ja-jp/deploy-monitor/auth0-cli)を行ってください。</Callout>

    既存ユーザーのメタデータを設定または更新するには、[Update a Userエンドポイント](/docs/ja-jp/api/management/v2/users/patch-users-by-id) (`PATCH /users/{id}`) を使用し、同様に`user_metadata`と`app_metadta`のボディパラメーターを指定します。

    <Accordion title="例：既存ユーザーのメタデータを更新">
      たとえば、次のメタデータ値を持つユーザーを作成したとします。

      ```json
      {
          "email": "jane.doe@example.com",
          "user_metadata": {
              "hobby": "surfing"
          },
          "app_metadata": {
              "plan": "full"
          }
      }
      ```

      ```json
              "home": "123 Main Street, Anytown, ST 12345"
          }
      }
      ```

    既存ユーザーのメタデータを更新する場合、オブジェクトにマージされるのはルートレベルのプロパティのみです。それより下位のプロパティはすべて置き換えられます。

    <Accordion title="例：メタデータのサブプロパティを更新する">
      たとえば、ユーザーの勤務先住所を内部プロパティとして新たに追加するには、`addresses` プロパティの内容をすべて含める必要があります。`addresses` オブジェクトはルートレベルのプロパティなので、ユーザーを表す最終的な JSON オブジェクトにマージされますが、そのサブプロパティはマージされません。

      ```json
      {
        "user_metadata": {
          "addresses": {
            "home": "123 Main Street, Anytown, ST 12345",
            "work": "100 Industrial Way, Anytown, ST 12345"
          }
        }
      }
      ```

  <Tab title="`post-login` アクション">
    `post-login`トリガーを構成すると、ユーザーのログインフローの一部として`user_metadata`と`app_metadata`を変更できます。

    ログイン後トリガーは、アプリケーション固有のデータをユーザープロファイルに保存する、ユーザーのオペレーションログを記録する、<Tooltip tip="Security Assertion Markup Language（SAML）：2者間でパスワードを使わずに認証情報を交換できるようにする標準化されたプロトコル。" cta="用語集を表示" href="/docs/ja-jp/glossary?term=SAML">SAML</Tooltip>属性をメタデータフィールドにマッピングする、負荷の高いオペレーションの結果をユーザープロファイルにキャッシュして以降のログインで再利用する、といったタスクに便利です。

    `post-login`の`api`オブジェクトには、このトリガーで実行できる一般的なオペレーションが用意されています。ユーザーメタデータを管理するには、`api.user.setAppMetadata`メソッドと`api.user.setUserMetadata`メソッドを使用します。たとえば、特定のユーザーに対してある動作が複数回実行されないようにするには、次のようなアクションを使用できます。

    ```js
    exports.onExecutePostLogin = async (event, api) => {
      if (event.user.app_metadata.didAnExpensiveTask) {
        console.log(`Skipping the expensive task because it already occurred for ${event.user.email}.`);

        return;
      }
      // 負荷の高いタスクを実行する
      api.user.setAppMetadata("didAnExpensiveTask", true);
    };
    ```

    ここでは、アクションの冒頭に、このユーザーに対して負荷の高い処理をすでに実行済みかどうかを確認するチェックを追加しています。メタデータフィールドが存在する場合は、関数から戻ります。

    アクションの最後では、`api.user.setAppMetadata`を呼び出して、ユーザーオブジェクトにメタデータを保存することを指示します。アクションは、各トリガーの実行終了時にユーザープロファイルを単一のオペレーションとして更新します。`setUserMetadata`が複数回呼び出された場合、それらが同じフロー内の別々のアクションで呼び出されたものであっても、アクションがユーザープロファイルを更新するのはトリガーの実行終了時の1回だけです。

    <Callout icon="file-lines" color="#0EA5E9" iconType="regular">
      `setUserMetadata`や`setAppMetadata`の複数の呼び出しは、別々のアクションから行われたものであっても、トリガーの実行終了時に1回のユーザープロファイル更新としてまとめて処理されます。
    </Callout>

    [`api.redirect.sendUserTo()`によるリダイレクト](/docs/ja-jp/customize/actions/redirect-with-actions)が発生した場合、保留中のユーザーメタデータやアプリメタデータの更新は、ユーザーが外部サイトにリダイレクトされる前にユーザープロファイルへ適用されます。

    ```javascript
    // 認証時に取得したaccessTokenを使ってgetUserInfoを呼び出します
    ```

## メタデータの読み取り {#read-metadata}

    <Tooltip tip="Management API：顧客が管理タスクを実行するための製品です。" cta="用語集を表示" href="/docs/ja-jp/glossary?term=Management+API">Management API</Tooltip>を使用すると、ルールでメタデータを読み取ることができます。また、`user_metadata`では、次のようなプロファイル関連の情報を検索することもできます。

    * `name`
    * `nickname`
    * `given_name`
    * `family_name`

    例として、メールアドレスが `jane.doe@example.com` のユーザーに次のメタデータが保存されているとします:

    ```json
    {
        "email": "jane.doe@example.com",
        "user_metadata": {
            "hobby": "surfing"
        },
        "app_metadata": {
            "plan": "full"
        }
    }
    ```

    上記のメタデータの例を使うと、[Auth0ルール](/docs/ja-jp/customize/rules)内や[Management API](/docs/ja-jp/manage-users/user-accounts/metadata)の呼び出しで、データセット内の特定の項目を次のように参照できます。

    ```js
    console.log(user.email); // "jane.doe@example.com"
    console.log(user.user_metadata.hobby); // "surfing"
    console.log(user.app_metadata.plan); // "full"
    ```

    有効なJSONスニペットであれば、どれでもメタデータとして使用できます。`user.app_metadata` はデフォルトで `Undefined` です。

    <Accordion title="例：メタデータに基づく条件付き処理">
      ユーザーのロールに応じて判断できます。

      ```javascript
      function(user, context, callback){
        user.app_metadata = user.app_metadata || {};
        if (user.app_metadata.roles.indexOf('writer')){
          // 実行するコード
        }
      }
      ```

      色の好みなど、特定の好みに基づいて判断することができます：

      ```javascript
      function(user, context, callback){
        user.user_metadata = user.user_metadata || {};
        if (user.user_metadata.preferences.color === 'black'){
          // 実行するコード
        }
        ...
      }
      ```
    </Accordion>

### アプリケーションメタデータの読み取り (clientMetadata) {#read-application-metadata-clientmetadata}

    アプリケーションメタデータ (`clientMetadata`) は、`context` オブジェクトのトップレベルにある任意のプロパティです。既存のアプリケーションでは、このプロパティに値は設定されていません。

    ```javascript
    function(user, context, callback){
      context.clientMetadata = context.clientMetadata || {};
      if (context.clientMetadata.usersuppliedkey1 === 'black'){
        // このコードはユーザーに対して実行されません
      }
      ...
    }
    ```

## メタデータの更新 {#update-metadata}

    ルールを使用すると、Auth0がIdPから受け取ったSAML属性を`user_metadata`または`app_metadata`にマッピングできます。

### アプリのメタデータの更新 {#update-app-metadata}

    ユーザーに管理者ロールを追加するには：

    ```javascript
    function(user, context, callback){
      user.app_metadata = user.app_metadata || {};
      // レスポンスに含まれる app_metadata を更新する
      user.app_metadata.roles = user.app_metadata.roles || [];
      user.app_metadata.roles.push('administrator');

      // app_metadata の更新を永続化する
      auth0.users.updateAppMetadata(user.user_id, user.app_metadata)
        .then(function(){
          callback(null, user, context);
        })
        .catch(function(err){
          callback(err);
        });
    }
    ```

    その結果、ユーザープロファイルの詳細は次のような JSON で表されます：

    ```json
    {
      "user_id": "jdoe",
      "email": "john.doe@example.com",
      "app_metadata": {
        "roles": [ "writer", "administrator" ]
      },
      "user_metadata": {
        "preferences": {
          "color": "blue"
        }
      }
    }
    ```

### ユーザーメタデータを更新する {#update-user-metadata}

    ユーザーの `fontSize` 設定をユーザープロファイルに追加するには、次の手順を実行します。

    ```javascript
    function(user, context, callback){
      user.user_metadata = user.user_metadata || {};
      // レスポンスに含まれる user_metadata を更新する
      user.user_metadata.preferences = user.user_metadata.preferences || {};
      user.user_metadata.preferences.fontSize = 12;

      // user_metadata の更新内容を保存する
      auth0.users.updateUserMetadata(user.user_id, user.user_metadata)
        .then(function(){
          callback(null, user, context);
        })
        .catch(function(err){
          callback(err);
        });
    }
    ```

    これにより、ユーザープロファイルの詳細は次のような JSON で表されます。

    ```json
    {
      "user_id": "jdoe",
      "email": "john.doe@example.com",
      "app_metadata": {
        "roles": [ "writer" ]
      },
      "user_metadata": {
        "preferences": {
          "color": "blue",
          "fontSize": 12
        }
      }
    }
    ```

### アプリとユーザーのメタデータを同時に更新する {#update-app-and-user-metadata-simultaneously}

    ルールの処理時間を短縮するには、同じルール内で `app_metadata` と `user_metadata` の両方を更新します。

    ```javascript expandable
    function(user, context, callback){

      var q = require('q');

      user.app_metadata = user.app_metadata || {};
      user.user_metadata = user.user_metadata || {};
      // レスポンスに含まれる user_metadata を更新する
      user.user_metadata.preferences = user.user_metadata.preferences || {};
      user.user_metadata.preferences.fontSize = 12;

      // レスポンスに含まれる app_metadata を更新する
      user.app_metadata.roles = user.app_metadata.roles || [];
      user.app_metadata.roles.push('admin');

      // app_metadata の更新を永続化する
      var appMetadataPromise  = auth0.users.updateAppMetadata(user.user_id, user.app_metadata);

      // user_metadata の更新を永続化する
      var userMetadataPromise = auth0.users.updateUserMetadata(user.user_id, user.user_metadata);

      // q ライブラリを使用してすべての Promise の完了を待機する
      q.all([userMetadataPromise, appMetadataPromise])
        .then(function(){
          callback(null, user, context);
        })
        .catch(function(err){
          callback(err);
        });
    }
    ```

    これにより、ユーザープロファイルの詳細は次のような JSON で表現されます。

    ```json
    {
      "user_id": "jdoe",
      "email": "john.doe@example.com",
      "app_metadata": {
        "roles": [ "writer", "admin" ]
      },
      "user_metadata": {
        "preferences": {
          "color": "blue",
          "fontSize": 12
        }
      }
    }
    ```

## メタデータを削除 {#delete-metadata}

### アプリメタデータのプロパティと値を削除する {#delete-app-metadata-properties-and-values}

    プロパティを削除するには、そのプロパティの値を `null` に設定します。

#### ユーザーのロール削除の例 {#delete-users-roles-example}

    ユーザーのロールを削除するには、次のサンプルRuleを使用します：

    ```javascript
    function(user, context, callback){
      user.app_metadata = user.app_metadata || {};
      // レスポンスに含まれる app_metadata を更新する
      user.app_metadata.roles = null;

      // app_metadata の更新を永続化する
      auth0.users.updateAppMetadata(user.user_id, user.app_metadata)
        .then(function(){
          callback(null, user, context);
        })
        .catch(function(err){
          callback(err);
        });
    }
    ```

    その結果、ユーザープロファイルの JSON 表現は次のようになります。

    ```json
    {
      "user_id": "jdoe",
      "email": "john.doe@example.com",
      "app_metadata": { },
      "user_metadata": {
        "preferences": {
          "color": "blue"
        }
      }
    }
    ```

#### 単一のプロパティ値を削除する例 {#delete-single-property-value-example}

    プロパティの値を1つだけ削除するには、その値を指定して削除します。たとえば、ユーザープロファイルから `writer` ロールを削除するには、次のようにします。

    ```javascript
    function(user, context, callback){
      user.app_metadata = user.app_metadata || {};
      user.app_metadata.roles = user.app_metadata.roles || [];

      var index = user.app_metadata.roles.indexOf('writer');

      if (index !== -1){
        // レスポンスに含まれるapp_metadataを更新します
        user.app_metadata.roles.splice(index, 1);
      }

      // app_metadataの更新内容を保存します
      auth0.users.updateAppMetadata(user.user_id, user.app_metadata)
        .then(function(){
          callback(null, user, context);
        })
        .catch(function(err){
          callback(err);
        });
    }
    ```

    その結果、ユーザープロファイルは次のような JSON で表現されます：

    ```json
    {
      "user_id": "google-oauth2|1234",
      "email": "john.doe@gmail.com",
      "app_metadata": {
        "roles": [ ]
      },
      "user_metadata": {
        "preferences": {
          "color": "blue"
        }
      }
    }
    ```

    `roles` プロパティは残っていますが、値は入っていません。

### ユーザーメタデータのプロパティと値を削除する {#delete-user-metadata-properties-and-values}

    ユーザーの色設定を削除するには：

    ```javascript
    function(user, context, callback){
      user.user_metadata = user.user_metadata || {};
      // レスポンスに含まれる user_metadata を更新する
      user.user_metadata.preferences = user.user_metadata.preferences || {};
      delete user.user_metadata.preferences.color;

      // user_metadata の更新を永続化する
      auth0.users.updateUserMetadata(user.user_id, user.user_metadata)
        .then(function(){
          callback(null, user, context);
        })
        .catch(function(err){
          callback(err);
      });
    }
    ```

    これにより、ユーザープロファイルの詳細は次のような JSON で表されます：

    ```json
    {
      "user_id": "jdoe",
      "email": "john.doe@example.com",
      "app_metadata": {
        "roles": [ "writer" ]
      },
      "user_metadata": {
        "preferences": { }
      }
    }
    ```
