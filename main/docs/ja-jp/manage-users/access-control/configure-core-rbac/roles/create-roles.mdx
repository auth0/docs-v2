Auth0 Dashboard または <Tooltip tip="Management API: 顧客が管理タスクを実行できるようにする製品。" cta="用語集を見る" href="/docs/ja-jp/glossary?term=Management+API">Management API</Tooltip> を使用して、[ロール](/docs/ja-jp/manage-users/access-control/rbac)を作成できます。ロールは API Authorization Core の機能セットと連携して機能します。

Auth0 では、2 種類のロールを作成できます。

* テナントロール: テナント全体に適用され、任意のユーザーに割り当てることができます。
* 組織 ロール: 特定の 組織 にスコープが設定されます。ユーザーは、所属する 組織 ごとに異なる 組織 ロールを持つことができます。詳細については、[組織 Roles](/docs/ja-jp/manage-users/organizations/organization-roles)を参照してください。

<ReleaseStageNotice feature="組織 Roles" stage="ea" terms="true" contact="Auth0 Support" />

<div id="prerequisites">
  ## 前提条件
</div>

* ロールベースのアクセス制御 (RBAC) を正しく機能させるには、Auth0 Dashboard または Management API を使用して、API で RBAC を有効にする必要があります。Authorization Core の機能は Authorization Extension とは異なります。比較については、[Authorization Core と Authorization Extension の比較](/docs/ja-jp/manage-users/access-control/authorization-core-vs-authorization-extension)をご覧ください。
* <Tooltip tip="Auth0 Dashboard: サービスを設定するための Auth0 のメイン製品です。" cta="用語集を見る" href="/docs/ja-jp/glossary?term=Auth0+Dashboard">Auth0 Dashboard</Tooltip> で [API を設定](/docs/ja-jp/get-started/auth0-overview/set-up-apis) します。
* 権限は事前定義された値から取得されます。権限の一覧が空の場合は、API に[権限を追加](/docs/ja-jp/get-started/apis/add-api-permissions)する必要があります。

<div id="create-a-tenant-role">
  ## テナント ロールを作成する
</div>

テナント ロールは テナント 全体に適用され、組織のメンバーシップにかかわらず、任意のユーザーに割り当てることができます。

<Tabs>
  <Tab title="Auth0 Dashboard">
    1. [Dashboard &gt; User Management &gt; Roles](https://manage.auth0.com/#/roles)に移動し、**ロールの作成**を選択します。
    2. ロールに名前を付け、説明を追加してから、**Create**を選択します。
  </Tab>

  <Tab title="Management API">
    [ロールの作成エンドポイント](/docs/ja-jp/api/management/v2#!/Roles/post_roles)に`POST`呼び出しを行います。`MGMT_API_ACCESS_TOKEN`、`ROLE_NAME`、`ROLE_DESC`のプレースホルダー値は、それぞれManagement APIの<Tooltip tip="アクセストークン：APIにアクセスするための、不透明な文字列またはJWT形式の認可資格情報。" cta="用語集を表示" href="/docs/ja-jp/glossary?term=access+token">アクセストークン</Tooltip>、ロール名、ロールの説明に置き換えてください。

    <Callout icon="file-lines" color="#0EA5E9" iconType="regular">Auth0 CLIを使用していますか？まだの場合は、このコマンドを実行する前に[CLIセッションを設定して認証](/docs/ja-jp/deploy-monitor/auth0-cli)してください。</Callout>


<div id="create-an-organization-role">
  ## 組織ロールを作成する
</div>

組織ロールは、組織の管理画面から作成します。テナント管理者は、組織ごとに最大350個の組織ロールを作成できます。

<Tabs>
  <Tab title="Auth0 Dashboard">
    1. [Auth0 Dashboard &gt; 組織](https://manage.auth0.com/#/organizations)に移動し、組織を選択します。
    2. **ロール**タブを選択し、**ロールの作成**を選択します。
    3. ロール名と説明を入力し、**Create**を選択します。
  </Tab>

  <Tab title="Management API">
    [Create Role endpoint](/docs/ja-jp/api/management/v2#!/Roles/post_roles)に`POST`リクエストを送信します。`type`を`"organization"`に設定し、`owner_id`に組織IDを設定します。`MGMT_API_ACCESS_TOKEN`、`ROLE_NAME`、`ROLE_DESC`、`ORG_ID`のプレースホルダー値は、それぞれManagement APIの<Tooltip tip="アクセストークン: APIへのアクセスに使用する、不透明な文字列またはJWT形式のAuthorization認証情報。" cta="用語集を見る" href="/docs/ja-jp/glossary?term=access+token">アクセストークン</Tooltip>、ロール名、ロールの説明、組織IDに必ず置き換えてください。

    <Tabs>
      <Tab title="Auth0 CLI">
        ```bash
        auth0 api post "roles" \
          --data '{ "name": "ROLE_NAME", "description": "ROLE_DESC", "type": "organization", "owner_id": "ORG_ID" }'
        ```
      </Tab>

      <Tab title="cURL">
        ```bash cURL
        curl --request POST \
          --url 'https://{yourDomain}/api/v2/roles' \
          --header 'authorization: Bearer MGMT_API_ACCESS_TOKEN' \
          --header 'cache-control: no-cache' \
          --header 'content-type: application/json' \
          --data '{ "name": "ROLE_NAME", "description": "ROLE_DESC", "type": "organization", "owner_id": "ORG_ID" }'
        ```
      </Tab>
    </Tabs>

    | **値**                   | **説明**                                                                          |
    | ----------------------- | ------------------------------------------------------------------------------- |
    | `MGMT_API_ACCESS_TOKEN` | スコープ`create:roles`を持つ[Management API用アクセストークン](/docs/ja-jp/api/management/v2/tokens)。 |
    | `ROLE_NAME`             | 作成する組織ロールの名前。組織内で一意である必要があります。                                                  |
    | `ROLE_DESC`             | ロールのわかりやすい説明。                                                                   |
    | `ORG_ID`                | ロールを作成する組織のID。                                                                  |

    レスポンスには、ロールがorganizationにスコープされていることを示す`type: "organization"`と`owner_id`が含まれます。
  </Tab>
</Tabs>
